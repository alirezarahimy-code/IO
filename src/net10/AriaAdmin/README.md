# آریا ادمین — برش ۱ (فقط هسته، هنوز وب‌سایت نیست)

`Core/AriaAdmin.Core.csproj` explicitly targets `net10.0` and compiles the **25 real files** of `src/T5Web/T5Web.Domain/` and `src/T5Web/T5Web.Application/` by read-only source links. Both layers are free of System.Web/Framework/x86 engine references; C# is deliberately 7.3 with `Nullable=disable` (not `annotations`). `Tests/AriaAdmin.Core.Tests.csproj` is a standalone no-NuGet `net10.0` executable with nine deterministic synthetic assertions from the current rewrite's `T01/T02/T03/T06` plus no-phantom-device and report-marker checks. The fixture is `Tests/golden.json`; it contains no real people, credentials or device traffic.

This is an **intermediate slice**, not an independent deployable web product: SQL/Data, IIS Windows authentication, Razor views, old routes, the calculated report engine, device commands and all web flows remain TODO/BLOCKED. The project links current rewrite sources until owned copies are functionally reviewed, then the links must be replaced before standalone release. Compiled and ran 9/9 on **both** Ubuntu (SDK 10.0.112) and Windows (SDK 10.0.113) in independent CI [40399185543](https://github.com/alirezarahimy-code/IO/actions/runs/40399185543) with `nuget.offline.config` (`<clear/>` sources), no `setup-dotnet` or silently downloaded package. This proves only a portable core and nine synthetic *rewrite* assertions. The ledger marks 41 related rows `MAPPED`, not original parity `TESTED`. Missing SDK or future test failure still fails the job.

No x86 target is set: these Domain/Application files do not load x86/native dependencies. No product version is assigned. Aria Admin is compared to its **own** `T5Web [3.5.7]` reference, not to Aria/TWF; the new core tests only compare narrow *rewrite* assertions and do not prove original behaviour.

## برش ۲: پوستهٔ وب fail-closed (AA-Web-01؛ هنوز نیازمند تأیید CI)

`Web/AriaAdmin.Web.csproj` یک میزبان واقعی **ASP.NET Core MVC با هدف `net10.0`** است، نه کتابخانهٔ قابل‌حملِ جایگزین وب. فقط مسیرهای `Home/Index` (انتقال به داشبورد)، `Dashboard/Index` و `Diagnostics/Index` (تا اثبات داده و مجوزها **۵۰۳**)، `Account/NoAccess` (نمای Razor فارسی با **۴۰۳**) و `/health/live` (صرفاً زنده‌بودن پردازش) دارد. محتوای CSS از نسخهٔ کنونی همین محصول در مخزن کپی شده، تنها یک توضیح متنی نامرتبط حذف شده، و درخواست شبکه/CDN نمی‌فرستد. `RazorCompileOnBuild/Publish` روشن است.

در اجرای عادی، هویت فقط از `HttpContext.User` با نوع احراز هویت ویندوز گرفته می‌شود؛ هویت ناشناس **۴۰۱** و نبود سازگارکنندهٔ دیتابیس/مجوز **۵۰۳** است. هیچ هدر آزمایشی، رمز، حساب ساختگی یا جایگزین SQL در فایل اجرایی وب وجود ندارد. کلاس‌های هویت و دادهٔ آزمایشی صرفاً در اسمبلی جداگانهٔ `Web.Tests` ثبت می‌شوند تا روی Kestrel حلقهٔ محلی، ۱۲ آزمون HTTP/Razor/امنیتی و ۴۰ درخواست هم‌زمان اجرا شود؛ این آزمون‌ها نه IIS/Negotiate واقعی هستند، نه آزمون SQL، نه بار ۱۰۰ کاربر. بدون اثبات Windows/IIS و فهرست مجوزهای UserInfo/T5WebAccess **استقرار عملیاتی مجاز نیست**. مسیرهای دیگر عمداً ۴۰۴/۴۰۳/۴۰۱ می‌دهند؛ صفحهٔ عملیاتی ساختگی با وضعیت ۲۰۰ تحویل داده نشده است.
