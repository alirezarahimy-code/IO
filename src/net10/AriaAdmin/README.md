# آریا ادمین — برش ۱ (فقط هسته، هنوز وب‌سایت نیست)

`Core/AriaAdmin.Core.csproj` explicitly targets `net10.0` and compiles the **25 real files** of `src/T5Web/T5Web.Domain/` and `src/T5Web/T5Web.Application/` by read-only source links. Both layers are free of System.Web/Framework/x86 engine references; C# is deliberately 7.3 with `Nullable=disable` (not `annotations`). `Tests/AriaAdmin.Core.Tests.csproj` is a standalone no-NuGet `net10.0` executable with nine deterministic synthetic assertions from the current rewrite's `T01/T02/T03/T06` plus no-phantom-device and report-marker checks. The fixture is `Tests/golden.json`; it contains no real people, credentials or device traffic.

This is an **intermediate slice**, not an independent deployable web product: SQL/Data, IIS Windows authentication, Razor views, old routes, the calculated report engine, device commands and all web flows remain TODO/BLOCKED. The project links current rewrite sources until owned copies are functionally reviewed, then the links must be replaced before standalone release. Compiled and ran 9/9 on **both** Ubuntu (SDK 10.0.112) and Windows (SDK 10.0.113) in independent CI [40399185543](https://github.com/alirezarahimy-code/IO/actions/runs/40399185543) with `nuget.offline.config` (`<clear/>` sources), no `setup-dotnet` or silently downloaded package. This proves only a portable core and nine synthetic *rewrite* assertions. The ledger marks 41 related rows `MAPPED`, not original parity `TESTED`. Missing SDK or future test failure still fails the job.

No x86 target is set: these Domain/Application files do not load x86/native dependencies. No product version is assigned. Aria Admin is compared to its **own** `T5Web [3.5.7]` reference, not to Aria/TWF; the new core tests only compare narrow *rewrite* assertions and do not prove original behaviour.

## برش ۲: پوستهٔ وب fail-closed (AA-Web-01؛ CI مستقل تأیید کرد)

`Web/AriaAdmin.Web.csproj` یک میزبان واقعی **ASP.NET Core MVC با هدف `net10.0`** است، نه کتابخانهٔ قابل‌حملِ جایگزین وب. فقط مسیرهای `Home/Index` (انتقال به داشبورد)، `Dashboard/Index` و `Diagnostics/Index` (تا اثبات داده و مجوزها **۵۰۳**)، `Account/NoAccess` (نمای Razor فارسی با **۴۰۳**) و `/health/live` (صرفاً زنده‌بودن پردازش) دارد. محتوای CSS از نسخهٔ کنونی همین محصول در مخزن کپی شده، تنها یک توضیح متنی نامرتبط حذف شده، و درخواست شبکه/CDN نمی‌فرستد. `RazorCompileOnBuild/Publish` روشن است.

در اجرای عادی، هویت فقط از `HttpContext.User` با نوع احراز هویت ویندوز گرفته می‌شود؛ هویت ناشناس **۴۰۱** و نبود سازگارکنندهٔ دیتابیس/مجوز **۵۰۳** است. هیچ هدر آزمایشی، رمز، حساب ساختگی یا جایگزین SQL در فایل اجرایی وب وجود ندارد. کلاس‌های هویت و دادهٔ آزمایشی صرفاً در اسمبلی جداگانهٔ `Web.Tests` ثبت می‌شوند؛ روی Kestrel حلقهٔ محلی، ۱۲ آزمون HTTP/Razor/امنیتی و یک سناریوی ۴۰ درخواست هم‌پوشان **روی هر دو سیستم** در [CI 40400275908](https://github.com/alirezarahimy-code/IO/actions/runs/40400275908) با SDK 10.0.112 (Ubuntu) و 10.0.113 (Windows) انجام شد. restore/build/publish در Release با `nuget.offline.config` بدون منبع بسته اجرا شد و Razor/CSS منتشر شدند. اجرای نخست `40400131053` روی هر دو سیستم فقط در فرض نادرست آزمونِ متنِ URL انتقال شکست خورد؛ آزمون اصلاح شد و اجرای دوم ۱۲/۱۲ گذشت. این آزمون‌ها نه IIS/Negotiate واقعی هستند، نه آزمون SQL، نه بار ۱۰۰ کاربر. بدون اثبات Windows/IIS و فهرست مجوزهای UserInfo/T5WebAccess **استقرار عملیاتی مجاز نیست**. مسیرهای دیگر عمداً ۴۰۴/۴۰۳/۴۰۱ می‌دهند؛ صفحهٔ عملیاتی ساختگی با وضعیت ۲۰۰ تحویل داده نشده است.

## برش AA-DIR-01 — قرائتِ دوکاتالوگیِ ادمین، بدون فعال‌سازی در محصول

`Web/Data/ReadOnlySqlDirectory.cs` مرزی مالکیت‌دار و **فقط برای آریا ادمین** است: تصویر محدود و بدون `Password` از `UserInfo` در کاتالوگ Personnel را با پارامتر `@UserName` می‌خواند، پس از رد نشان صفر/وب‌کاربرِ غیرفعال/تاریخ خروج/شناسهٔ تکراری، ردیف‌های `T5WebAccess` را از کارخانهٔ **جداگانهٔ T5** با `@BadgeNumber` می‌خواند. SQL ثابت، فقط SELECT و ADO.NET استاندارد است؛ ورودی هویت در متن فرمان جای‌گذاری نمی‌شود، خطای driver در پاسخ نمی‌آید، دسترسی ناشناخته/نامعتبر یا Deny-only اجازه نمی‌سازد و لغو درخواست منتقل می‌شود. این فقط قرارداد ستون‌ها و سیاست بازنویسی جاری **همین محصول** `src/T5Web/` را نقطهٔ شروع می‌گیرد. برای ادمین اصل `T5Web [3.5.7]` هنوز **هیچ golden مجوز/HTTP یا SQL** نداریم؛ منطق چنددامنه و نام کاربری، مجوزهای قدیمی، ثبات بین دو کاتالوگ، اسکیمای SQL Server 2016 و زمان انقضای نشست باید جداگانه ممیزی شوند. تفاوت‌های ایمنی اجباری و موقت نسبت به بازنویسی: نام تکراری به‌جای `TOP 1` رد می‌شود، UPN بدشکل و ردیف مجوز نامعتبر fail-closed می‌شوند و تنها ردیف Deny ورود نمی‌سازد؛ این تغییرها ادعای برابری با اصل نیستند.

**اقدام عملیاتی عمداً بسته می‌ماند:** این کلاس `internal` است و در DI سایت منتشرشده ثبت نشده؛ `Program.cs` همچنان فقط `UnavailableAdminDirectory` دارد و برای درخواست داده پس از هویت ویندوزی **۵۰۳** می‌دهد. هیچ بستهٔ SQL، رشتهٔ اتصال، کلید، حساب حقیقی یا دستگاهی در کد یا CI گذاشته نشده است. `Directory.Tests` با `DataTableReader` و connection/commandهای کاملاً ساختگی، صرفاً مسیر تصمیم و bindشدن پارامترها را می‌آزماید؛ داده‌ها بر مبنای پارامتر فیلتر **نمی‌شوند** و این آزمون اتصال یا حتی اجرای SQL نیست. [CI 40452593388](https://github.com/alirezarahimy-code/IO/actions/runs/40452593388)، در Ubuntu/Windows با restore آفلاین **۷/۷** آزمون ساختگی و تمام **۱۲ job محصول** را گذراند؛ Web/Razor هر دو محصول نیز ۱۳/۱۳ آزمون HTTP قبلی را گذراندند. CIهای اولیهٔ `40452347879` (اخطار Nullable در تست) و `40452470161` (فرض اشتباه آزمون دربارهٔ UPN دارای دو `@`) عمداً قرمز ماندند و پس از اصلاح تکرار شدند. دفتر شش ردیف منبع ادمین را فقط با مقصد جزئی در وضعیت `TODO` نگه می‌دارد. پس از تثبیت provider مجاز از منبع آفلاین و داشتن SQL Server 2016 دوکاتالوگی **ایزوله با دادهٔ مصنوعی**، اسکیما/نقش/خطای اتصال و خروجی اصل همین ادمین باید در محیط مجاز سنجیده شوند؛ تا آن زمان اتصال به DI، استقرار IIS، بار ۱۰۰ کاربر عملیاتی و حکم آمادگی انتشار ممنوع است.
