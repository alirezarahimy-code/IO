# آریا ادمین — برش ۱ (فقط هسته، هنوز وب‌سایت نیست)

`Core/AriaAdmin.Core.csproj` explicitly targets `net10.0` and compiles the **25 real files** of `src/T5Web/T5Web.Domain/` and `src/T5Web/T5Web.Application/` by read-only source links. Both layers are free of System.Web/Framework/x86 engine references; C# is deliberately 7.3 with `Nullable=disable` (not `annotations`). `Tests/AriaAdmin.Core.Tests.csproj` is a standalone no-NuGet `net10.0` executable with nine deterministic synthetic assertions from the current rewrite's `T01/T02/T03/T06` plus no-phantom-device and report-marker checks. The fixture is `Tests/golden.json`; it contains no real people, credentials or device traffic.

This is an **intermediate slice**, not an independent deployable web product: SQL/Data, the verified shared-account login and IIS integration, Razor views, old routes, the calculated report engine, device commands and all web flows remain TODO/BLOCKED. The project links current rewrite sources until owned copies are functionally reviewed, then the links must be replaced before standalone release. Compiled and ran 9/9 on **both** Ubuntu (SDK 10.0.112) and Windows (SDK 10.0.113) in independent CI [40399185543](https://github.com/alirezarahimy-code/IO/actions/runs/40399185543) with `nuget.offline.config` (`<clear/>` sources), no `setup-dotnet` or silently downloaded package. This proves only a portable core and nine synthetic *rewrite* assertions. The ledger marks 41 related rows `MAPPED`, not original parity `TESTED`. Missing SDK or future test failure still fails the job.

No x86 target is set: these Domain/Application files do not load x86/native dependencies. No product version is assigned. Aria Admin is compared to its **own** `T5Web [3.5.7]` reference, not to Aria/TWF; the new core tests only compare narrow *rewrite* assertions and do not prove original behaviour.

## برش ۲: پوستهٔ وب fail-closed (AA-Web-01؛ CI مستقل تأیید کرد)

`Web/AriaAdmin.Web.csproj` یک میزبان واقعی **ASP.NET Core MVC با هدف `net10.0`** است، نه کتابخانهٔ قابل‌حملِ جایگزین وب. فقط مسیرهای `Home/Index` (انتقال به داشبورد)، `Dashboard/Index` و `Diagnostics/Index` (تا اثبات داده و مجوزها **۵۰۳**)، `Account/NoAccess` (نمای Razor فارسی با **۴۰۳**) و `/health/live` (صرفاً زنده‌بودن پردازش) دارد. محتوای CSS از نسخهٔ کنونی همین محصول در مخزن کپی شده، تنها یک توضیح متنی نامرتبط حذف شده، و درخواست شبکه/CDN نمی‌فرستد. `RazorCompileOnBuild/Publish` روشن است.

در **برش اولیهٔ ثبت‌شده در CI زیر**، هویت از `HttpContext.User` ویندوز گرفته می‌شد و نبودش ۴۰۱/`Negotiate` می‌داد؛ این فرض با قراردادِ اعلامیِ یک حساب/رمز مشترک ناسازگار تشخیص داده شد و **دیگر رفتار نسخهٔ کنونی نیست**. اکنون بدون اعتبارسنجِ همان حساب مشترک، production برای مسیرهای حفاظت‌شده **۵۰۳، بدون چالش رمز ویندوزی** است. هیچ هدر آزمایشی، رمز، حساب ساختگی یا جایگزین SQL در فایل اجرایی وب وجود ندارد. کلاس‌های هویت و دادهٔ آزمایشی صرفاً در اسمبلی جداگانهٔ `Web.Tests` ثبت می‌شوند؛ روی Kestrel حلقهٔ محلی، ۱۲ آزمون HTTP/Razor/امنیتی و یک سناریوی ۴۰ درخواست هم‌پوشان **روی هر دو سیستم** در [CI 40400275908](https://github.com/alirezarahimy-code/IO/actions/runs/40400275908) با SDK 10.0.112 (Ubuntu) و 10.0.113 (Windows) انجام شد. restore/build/publish در Release با `nuget.offline.config` بدون منبع بسته اجرا شد و Razor/CSS منتشر شدند. اجرای نخست `40400131053` روی هر دو سیستم فقط در فرض نادرست آزمونِ متنِ URL انتقال شکست خورد؛ آزمون اصلاح شد و اجرای دوم ۱۲/۱۲ گذشت. این آزمون‌ها نه IIS/Negotiate واقعی هستند، نه آزمون SQL، نه بار ۱۰۰ کاربر. بدون اثباتِ اعتبارسنجی همان نام/رمز مشترک در برابر اصل `T5Web [3.5.7]`، مجوزهای واقعی و IIS/SQL **استقرار عملیاتی مجاز نیست**. آزمون‌های آن برش ۴۰۴/۴۰۳/۴۰۱/۵۰۳ را سنجیدند؛ پوستهٔ تولیدیِ فعلی به دلیل فقدان ورود مشترک ۵۰۳ می‌دهد و صفحهٔ عملیاتی ساختگی با وضعیت ۲۰۰ تحویل داده نشده است.

## برش AA-DIR-01 — قرائتِ دوکاتالوگیِ ادمین، بدون فعال‌سازی در محصول

`Web/Data/ReadOnlySqlDirectory.cs` مرزی مالکیت‌دار و **فقط برای آریا ادمین** است: تصویر محدود و بدون `Password` از `UserInfo` در کاتالوگ Personnel را با پارامتر `@UserName` می‌خواند، پس از رد نشان صفر/وب‌کاربرِ غیرفعال/تاریخ خروج/شناسهٔ تکراری، ردیف‌های `T5WebAccess` را از کارخانهٔ **جداگانهٔ T5** با `@BadgeNumber` می‌خواند. SQL ثابت، فقط SELECT و ADO.NET استاندارد است؛ ورودی هویت در متن فرمان جای‌گذاری نمی‌شود، خطای driver در پاسخ نمی‌آید، دسترسی ناشناخته/نامعتبر یا Deny-only اجازه نمی‌سازد و لغو درخواست منتقل می‌شود. این فقط قرارداد ستون‌ها و سیاست بازنویسی جاری **همین محصول** `src/T5Web/` را نقطهٔ شروع می‌گیرد. برای ادمین اصل `T5Web [3.5.7]` هنوز **هیچ golden مجوز/HTTP یا SQL** نداریم؛ منطق چنددامنه و نام کاربری، مجوزهای قدیمی، ثبات بین دو کاتالوگ، اسکیمای SQL Server 2016 و زمان انقضای نشست باید جداگانه ممیزی شوند. تفاوت‌های ایمنی اجباری و موقت نسبت به بازنویسی: نام تکراری به‌جای `TOP 1` رد می‌شود، UPN بدشکل و ردیف مجوز نامعتبر fail-closed می‌شوند و تنها ردیف Deny ورود نمی‌سازد؛ این تغییرها ادعای برابری با اصل نیستند.

**اقدام عملیاتی عمداً بسته می‌ماند:** این کلاس `internal` است و در DI سایت منتشرشده ثبت نشده؛ `Program.cs` همچنان فقط `UnavailableAdminDirectory` دارد و تا تأیید هویت همان حساب مشترک و مجوزهای اصل، برای مسیر حفاظت‌شده **۵۰۳ بدون درخواست رمز دوم** می‌دهد. هیچ بستهٔ SQL، رشتهٔ اتصال، کلید، حساب حقیقی یا دستگاهی در کد یا CI گذاشته نشده است. `Directory.Tests` با `DataTableReader` و connection/commandهای کاملاً ساختگی، صرفاً مسیر تصمیم و bindشدن پارامترها را می‌آزماید؛ داده‌ها بر مبنای پارامتر فیلتر **نمی‌شوند** و این آزمون اتصال یا حتی اجرای SQL نیست. [CI 40452593388](https://github.com/alirezarahimy-code/IO/actions/runs/40452593388)، در Ubuntu/Windows با restore آفلاین **۷/۷** آزمون ساختگی و تمام **۱۲ job محصول** را گذراند؛ Web/Razor هر دو محصول نیز ۱۳/۱۳ آزمون HTTP قبلی را گذراندند. CIهای اولیهٔ `40452347879` (اخطار Nullable در تست) و `40452470161` (فرض اشتباه آزمون دربارهٔ UPN دارای دو `@`) عمداً قرمز ماندند و پس از اصلاح تکرار شدند. دفتر شش ردیف منبع ادمین را فقط با مقصد جزئی در وضعیت `TODO` نگه می‌دارد. پس از تثبیت provider مجاز از منبع آفلاین و داشتن SQL Server 2016 دوکاتالوگی **ایزوله با دادهٔ مصنوعی**، اسکیما/نقش/خطای اتصال و خروجی اصل همین ادمین باید در محیط مجاز سنجیده شوند؛ تا آن زمان اتصال به DI، استقرار IIS، بار ۱۰۰ کاربر عملیاتی و حکم آمادگی انتشار ممنوع است.

### ادامهٔ AA-DIR-02: آزمون HTTP با سازگارکنندهٔ SQL **فقط در اسمبلی آزمون**

در [CI 40453071454](https://github.com/alirezarahimy-code/IO/actions/runs/40453071454)، `Directory.Tests` از هفت سنجش مستقیم به **۹/۹ آزمون ساختگی روی هر دو سیستم** رسید و هر ۱۲ job محصول موفق شد. دو سناریوی تازه، میزبان واقعیِ MVC/Kestrel را با تزریق DI و هویتِ هدرِ **فقط در اسمبلی آزمون** راه می‌اندازند: شخصِ مجاز با ردیف‌های ساختگی Personnel/T5 به مسیرهای Diagnostics و Dashboard می‌رسد ولی هر دو همچنان **۵۰۳ بدون دادهٔ جعلی** می‌دهند؛ ناشناس **۴۰۱**، WebUser غیرفعال **۴۰۳** بدون مراجعه به T5 و خطای driver **۵۰۳ بدون افشای جزئیات** است. دو درخواستِ آزمونی اتصال‌های جداگانه و بسته‌شده دارند و کوکی/کش مجوز صادر نمی‌شود. این آزمون **هیچ** SQL واقعی، Windows principal واقعی، اصل `T5Web [3.5.7]`، IIS/ANCM یا بار عملیاتی اجرا نمی‌کند. هدر و سازگارکنندهٔ جعلی در فایل قابل‌انتشار ثبت نشده‌اند؛ تولید هنوز `UnavailableAdminDirectory`/۵۰۳ است و دفتر شش ردیفِ مقصد جزئی را `TODO` نگاه می‌دارد. برای فعال‌سازی واقعی گیت‌های provider آفلاین، دو SQL Server 2016 ساختگی، golden امنیت اصل و IIS مجاز باز هستند.

## اصلاح AA-AUTH-01 — همان نام/رمز سه برنامه، نه درخواست اعتبارنامهٔ دوم

کاربر صریحاً تأیید کرد که یک شخص در کل سامانه یک نام کاربری و یک رمز عبور دارد؛ در صورت داشتن مجوز و سطح مدیریتی می‌تواند به سه برنامهٔ موجود وارد شود. فرض قبلیِ «ادمین فقط با Windows/Negotiate وارد شود» برای محصول نهایی **مجاز نیست**؛ حتی اگر `Web.config` اصل mode ویندوز داشته باشد، این به‌تنهایی لزوم رمز جداگانه را ثابت نمی‌کند. در [CI 40454685627](https://github.com/alirezarahimy-code/IO/actions/runs/40454685627)، پوستهٔ production ادمین دیگر `WWW-Authenticate: Negotiate` نمی‌فرستد، هویت/رمز مستقل ادمین نمی‌گیرد و تا تأیید سازوکار همان حساب مشترک با `UnavailableSharedAccountSource` **۵۰۳** می‌دهد. فقط در test assembly پاسخ ۴۰۱ برای حساب ساختگیِ ناشناس و نقش‌های ساختگی آزمایش می‌شود؛ این ورود واقعی یا SSO نیست. همان CI ساخت/انتشار Razor آفلاین و **۱۳/۱۳** آزمون Web و **۹/۹** آزمون Directory را در Ubuntu/Windows گذراند؛ ۱۲ job موفق فقط fail-closed بودن را نشان می‌دهند، نه تکمیل ورود. قرارداد و گیت پذیرش: [`../IDENTITY_CONTRACT.fa.md`](../IDENTITY_CONTRACT.fa.md). مرز SQL ادمین هنوز internal/ثبت‌نشده است؛ تا golden اصل ادمین، اعتبارسنج مشترک، provider آفلاین، دو DB ساختگی و IIS مجاز، release `BLOCKED` است.
