# آریا — برش AR-Core-01 (فقط هستهٔ قابل‌حمل، نه وب‌محصول)

`Core/Aria.Core.csproj` به‌صراحت `net10.0` را هدف می‌گیرد و ۱۵ فایل Domain، سه سرویس Application (ماندهٔ مرخصی، دسترسی سازمانی، مدل نشست) و یک اجرای مجوزدهیِ بدون قفل را **فقط از بازنویسی همین محصول** در `src/TWF/` با پیوند فقط‌خواندنی کامپایل می‌کند. فایل مالکیتی `Core/Localization/PersianString.cs` تنها دو عبارت رد درخواست مرخصی را واژه‌به‌واژه از همان بازنویسی حمل می‌کند؛ منابع کامل UI و بنرِ نسخهٔ تأییدنشده به هسته وارد نمی‌شوند. این برش مستقل از آریا ادمین است و هنوز میزبان ASP.NET Core، کنترلر، Razor یا دسترسی واقعی به دیتابیس ندارد. C# فایل‌های پیوندشده 7.3 و `Nullable=disable` است؛ برای این اسمبلی x86 تنظیم نشده، چون هیچ DLL بومی یا وابستگی موتور اجرایی در آن بارگذاری نمی‌شود.

`TWF.Domain.Interfaces.IT5BackendAdapter` مرز صریحِ سازمان/تردد/موتور محاسباتی ویندوزی است، **نه** یک اجرای معتبر آن. DLLهای ۳۲بیتیِ موتورِ مرجع `TWF 4.28`، SQL و سازگارکنندهٔ خارجی عمداً در فرایند جدید وارد نشده‌اند؛ استفادهٔ عملیاتی بدون سازگارکنندهٔ جداگانه، آزمون Windows/x86 و خروجی طلایی نسخهٔ اصلی ممنوع است. سورس‌های پیوندی باید قبل از انتشار مستقل، با نسخهٔ مالکیتی بازبینی‌شده جایگزین شوند. نه قفل نرم‌افزاری/سخت‌افزاری تازه‌ای اضافه شده، نه شمارهٔ نسخهٔ تازه‌ای برای محصول اعلام شده است.

`Tests/Aria.Core.Tests.csproj` یک اجراکنندهٔ مستقل بدون NuGet و با ورودی ثابت `Tests/golden.json` دارد: ۱۱ آزمون مصنوعی برای تقویم شمسی و مرز سال/کبیسه، زمان فارسی، DTO سلامت دو کاتالوگ، قرارداد فعلیِ مجوزدهی بدون قفل، مدت نشست (فقط مدل، **نه رمزنگاری/کوکی وب**)، هویت مستقل هر فراخوانی، مقادیر شناسهٔ گردش کار نبود پیوند/اجرای موتور و متن دو پیام ردِ مرخصی. انتظارها از بخش‌های مشخص `src/TWF/TWF.Tests/Program.cs` و بازنویسی کنونی آمده‌اند؛ از باینری‌های `TWF 4.28` استخراج نشده‌اند. **هیچ** دسترسی به دادهٔ واقعی، رمز، کلید، دستگاه، دیتابیس یا اتصال تولیدی وجود ندارد. موفقیت ساخت/تست هسته برابری با نسخهٔ اصلی یا وب/IIS را ثابت نمی‌کند.

مبنای Framework همین بازنویسی طبق شواهد `src/net10/TEST_LOG.md` هنوز ساخته/اجرا نشده است: فایل‌های آزمون در میزبان واقعی Windows Framework کامپایل نمی‌شوند و هر ۴۷ ثبت آزمون آن تا این مرحله اجرا نشده‌اند. مقایسهٔ اصلی این محصول تنها با **`TWF 4.28`** انجام می‌شود؛ سایر محصولات معیار سنجش آن نیستند. تلاش نخست [CI 40401715759](https://github.com/alirezarahimy-code/IO/actions/runs/40401715759) روی هر دو سیستم در کامپایل `CS0234` متوقف شد: `LeaveBalanceService` به دو عبارت از فضای‌نام `TWF.Infrastructure.Localization` نیاز داشت. دو عبارت واژه‌به‌واژه از بازنویسی همین محصول در فایل مالکیتی محدود بالا جای‌گذاری و آزمون آن افزوده شد. اجرای مستقل [CI 40401991305](https://github.com/alirezarahimy-code/IO/actions/runs/40401991305) روی Ubuntu با SDK 10.0.112 و Windows با SDK 10.0.113 موفق شد: restore/build آفلاینِ `net10.0` و **۱۱/۱۱ آزمون مصنوعی در هر سیستم**. از ۹٬۸۳۷ ردیف دفتر، برای این برش فقط ۱۹ فایل پیوندی و ۴۹ نوع/عضو منتخب (جمعاً ۶۸ ردیف) `MAPPED` هستند؛ فایل/نوع کامل منابع متنی و دو پروژهٔ Framework با مقصد ناقص همچنان `TODO` هستند. هیچ ردیفی به‌دلیل این آزمون‌ها `TESTED`/هم‌ارز نسخهٔ اصلی نشده است.

## برش AR-Web-01 — میزبان حداقلی و بسته (تأیید محدود در CI)

`Web/Aria.Web.csproj` یک میزبان مستقل ASP.NET Core MVC/Razor با هدف صریح `net10.0` است و به **هستهٔ آریا** متصل می‌شود، نه به برنامهٔ مدیریت. تنها استایل عمومی آن عیناً از بازنویسی همین محصول کپی شده است (`SHA-256: 46b0ad2d13b7fcd095741db83a43cd2a6d826be80eb219678d0a43b97ffe3a49`)؛ درخواست داراییِ اینترنتی ندارد و صفحه‌ها راست‌به‌چپ فارسی‌اند. ساخت و انتشار Razor اجباری است.

**تغییر PORT اجباری/موقت، نه معادل نسخهٔ اصلی:** نسخهٔ فعلیِ بازنویسی آریا دو تعریف ناسازگار برای مدت نشست دارد (LoginManager دقیقه؛ Domain SessionManager ساعت) و در رمزنگاریِ MVC یک رمز پیش‌فرض ثابت دارد. بدون golden از `TWF 4.28`، کلیدِ مجاز، پایگاه‌داده، مجوزها، CAPTCHA و آزمون امنیتی، هیچ‌یک را بی‌صدا به کوکی Core تبدیل نمی‌کنیم. تأییدکنندهٔ واقعیِ Web همیشه `Unavailable` می‌دهد؛ حتی هدر و کوکیِ ارسالیِ کاربر ورود نمی‌سازند. صفحهٔ `GET /Login/Login` با Razor و وضعیت **۵۰۳** خبر می‌دهد و **فرم یا POST جمع‌آوری رمز وجود ندارد**. `/Home/Index` فقط پس از نشستِ واقعاً تأییدشده اجازهٔ رسیدن به کنترلر دارد و حتی در آزمون ساختگی **۵۰۳** است: موتور تردد/مرخصی و SQL پورت نشده‌اند. `Diagnostics/Health` و `Diagnostics/Schema` به‌جای سبز نشان‌دادن پایگاه‌داده یا افشای اسکیمای آن **۵۰۳** می‌دهند؛ `/health/live` فقط زنده‌بودن فرایند را با ۲۰۰ نشان می‌دهد. عملیات دیگر فراهم نشده‌اند. بهبود اختیاری در این برش ادعا نمی‌شود.

`Web.Tests` تنها در اسمبلی جداگانه، یک تأییدکنندهٔ نشست **کاملاً مصنوعی** و ساعت ثابت دارد تا ۱۲ سناریوی Kestrel/HTTP/Razor/امنیتی و ۴۰ درخواست هم‌پوشان را بدون رمز، SQL، دستگاه یا دیتای واقعی بررسی کند. هیچ هدر آزمایشی یا گزینهٔ فعال‌سازیِ آزمایشی در وب قابل‌انتشار نیست. این نه شبیه‌سازی کلاینت حقیقیِ نسخهٔ اصلی است، نه آزمون ۱۰۰ کاربر، نه آزمون HTTPS/IIS/SQL یا برابری مسیرها. تا زمان عبور از گیت‌های اصل/کوکی/موتور/Windows و IIS، **استقرار عملیاتی ممنوع است**. [CI 40402911019](https://github.com/alirezarahimy-code/IO/actions/runs/40402911019) روی Ubuntu با SDK 10.0.112 و Windows با SDK 10.0.113 موفق شد: restore/build/publish آفلاینِ Web/Razor/CSS در Release و **۱۲/۱۲ آزمون HTTP مصنوعی در هر دو سیستم**. آزمون‌ها دست‌کم حالت‌های نشستِ ناشناس/ردشده/منقضی/خطای تأیید، نبود POST ورود، CSP/دارایی محلی، ۵۰۳ بدون داده، و ۴۰ درخواست هم‌پوشان را پوشش می‌دهند؛ **خود IIS، کوکی واقعی نسخهٔ اصلی و پایگاه‌داده در این CI اجرا نشدند**. دفتر فقط ردیف CSS کپی‌شدهٔ دقیق را `MAPPED` کرده است؛ ۲۶ ردیف مسیر/ویو/پروژهٔ دارای مقصد ناقص همچنان `TODO` و همهٔ رفتارهای اصلی بدون نتیجهٔ طلایی‌اند.

## برش AR-CAT-01 — دو اتصال مستقل بدون provider یا اتصال عملیاتی

`Core/Data/DualCatalogConnectionProbe.cs` یک مرز مالکیت‌دار `net10.0` برای **همین محصول** است: سازنده برای کاتالوگ Personnel و T5 دو کارخانهٔ اتصال ADO.NET مستقل می‌خواهد، برای هر بررسی اتصال تازه می‌سازد، باز/بسته‌شدن و وضعیت `Open` را بررسی می‌کند، شکست یکی را با دیگری اشتباه نمی‌گیرد، لغو را به فراخواننده منتقل می‌کند و متن خطای driver (احتمالاً حاوی آدرس/اطلاعات اتصال) را به خروجی نمی‌برد. این برش جای `TwfDataRepository`، پرس‌وجو/اسکیما/نقش و آزمون SQL Server 2016 نیست. تفاوت ایمنیِ اجباری با بازنویسی جاری TWF: در آن، وقتی factory وجود ندارد، صرفِ وجود رشته‌های اتصال می‌تواند سلامت دو پایگاه را «سبز» کند؛ این برش بدون کارخانه اصلاً ساخته نمی‌شود. رفتار اصل `TWF 4.28` برای سلامت پایگاه هنوز سنجیده نشده است. هیچ provider یا connection string در محصول جدید قرار داده/ثبت نشده و Web همچنان `/Diagnostics/Health` را **۵۰۳** می‌دهد؛ حتی اگر آزمون‌های اتصال ساختگی سبز باشند، سرویس عملیاتی فعال نمی‌شود.

[CI 40451886767](https://github.com/alirezarahimy-code/IO/actions/runs/40451886767) در Ubuntu/Windows با SDKهای پیش‌نصب ‎.NET 10 و restore آفلاین، هسته و اجراکنندهٔ جداگانهٔ `Catalog.Tests` را ساخت و **۷/۷ آزمونِ صرفاً ساختگی** را در هر سیستم گذراند: باز/بسته‌شدن دو اتصال، نبود کارخانه، شکست‌های جداگانه، عدم افشای متن خطا، بازنشدن، لغو و ۱۰۰ بررسی هم‌پوشانِ in-process. [CI 40451625520](https://github.com/alirezarahimy-code/IO/actions/runs/40451625520) فقط نمونه‌های **قالب‌بندی زمان** باینری اصل آریا را دوباره گذراند؛ اصلاً SQL/HTTP اصل را نخواند. دفتر ردیف `CheckDatabaseHealth()` را با مقصد جزئی و وضعیت `TODO` نگه می‌دارد. گام برگشت‌پذیر بعدی: فقط پس از ارائهٔ provider آفلاینِ تأییدشده و دو کاتالوگ ایزولهٔ SQL Server 2016 با دادهٔ ساختگی، اتصال‌ها، اسکیمای ضروری، مجوز خواندن و خطای fail-closed را جداگانه روی هر کاتالوگ بسنجیم؛ تا آن زمان هیچ استقرار یا ادعای ۱۰۰ کاربر عملیاتی مجاز نیست.
