# Ledger contract and limitations

`LEDGER.csv` is generated by `src/net10/tools/LedgerGenerator` from the **read-only** current rewrites, their respective originals, the supplementary T5V3 desktop assembly set and the explicitly excluded Link5 binary set. Its stable ID is `SYSTEM:KIND:sha256(system|kind|source|signature)[0:16]`; line numbers and file hashes are evidence fields, never part of the member ID. Re-run the generator with the preinstalled .NET 10 SDK and `nuget.offline.config` (empty package sources). No Roslyn NuGet restore: its two managed assemblies are referenced from the installed SDK. CI uploads the first output for review. After freezing `LEDGER.csv`, `ledger-check.py --inventory` fails on any added/removed ID or changed source SHA until the mapping is reviewed.

| Column | Meaning |
| --- | --- |
| `system` | `ARIA` only against TWF; `ARIA_ADMIN` only against T5Web (T5V3 desktop supplementary); `EXTERNAL_LINK5` inventory only, out of scope. |
| `kind` | File and member declarations from Roslyn (`CS_FILE`, `TYPE`, `METHOD`, `FIELD`, `ACTION_CANDIDATE`, etc.), view/link, config *key without value*, SQL candidate, project dependency, binary PE metadata, original action decision, or a flagged parse gap. |
| `source` / `signature` / `source_sha256` / `line` | Paths relative to this checkout; source hash for reproducibility, omitted for restricted `.mdf/.ldf/.bak/.dat`; names not contents for secrets. |
| `legacy_reference` | **Same product's** original location. Never infer Aria equivalence from Aria Admin or vice versa. |
| `destination` | Empty until an actual new-app member/route/asset mapping is demonstrated. A planned route is not a TESTED destination. |
| `status` | `TODO` (needs mapping), `MAPPED` (mapped, not proven), `TESTED` (requires new-path destination and runnable evidence), `BLOCKED`, `N-A` (documented with evidence), `REFERENCE_ONLY`, or `OUT_OF_SCOPE`. Link5 rows are `OUT_OF_SCOPE`; supplementary desktop DLLs are reference-only. A prior legacy `drop` remains `TODO` until approved with evidence. |
| `evidence` / `notes` | CI run and test fixture identifiers for TESTED, documented rationale for N-A, explicit source gap where needed. Do **not** store secrets or real data. |

Roslyn inventories C# declarations and public controller-action **candidates**; it does not establish which methods route under MVC, authorize, bind, render, or compute the same outputs. The Razor reader inventories view files and static links, **not** Razor compilation. The SQL scanner finds keyword candidates, **not** executable complete statements or cross-catalog correctness. The assembly metadata reader does not execute vendor code; controller public methods are candidates, not all HTTP actions. Existing `legacy-actions.csv` contains 343 decisions including 87 drops; those are not parity evidence. Generated source gaps must be kept as BLOCKED, not silently omitted.

`ledger-check.py --inventory` checks counts/IDs/static coverage only. `ledger-check.py --release` deliberately fails while any in-scope row is TODO/MAPPED/BLOCKED or any TESTED row lacks a tested destination/evidence. Neither check can alone certify route/output parity: separately require product CI, synthetics, view compilation, IIS/SQL, authorization, load, and rollback evidence. The CI job must report its actual SDK version; missing SDK or offline packages are `NEEDS-INFRA`, never an online restore hidden by the inventory script.

**Artifact transport note:** Arena cannot retrieve GitHub Actions' Azure Blob artifact URL. On the first verified push run only, the ledger workflow has `contents: write` and, after passing the offline generator and count/ID validator, commits *only* `src/net10/LEDGER.csv` directly to `arena/a4df3135-io` with a non-force `git push`. PR jobs do not write. A pre-existing ledger is never overwritten automatically; it must match freshly generated IDs/source hashes. Fetch the fixed branch and recheck locally before mapping any row. This is necessary for a tracked deliverable, not evidence of parity.
