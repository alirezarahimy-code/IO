# ۰۱ — اصول حاکم بر بازنویسی T5Web («آریا ادمین»)

> **نام محصول:** این بازنویسی با نام **«آریا ادمین» / Aria Admin** (کد `ARIA-ADMIN`، نسخه `5.0`)
> ثبت شده است — قرینه همان ثبتی که برای بازنویسی `TWF 4.28` با نام «آریا» انجام شد.
> نام پوشه (`src/T5Web`) و مسیر فایل‌ها دست‌نخورده می‌ماند؛ هویت محصول در
> `T5Web.Web/Content/AriaAdminBranding.cs` است و آزمون `T30` آن را قفل می‌کند.

این سند «قانون اساسی» پورتال T5Web است. هر تصمیم فنی که با این هفت اصل تعارض داشته باشد
بازبینی می‌شود، حتی اگر سریع‌تر یا مدرن‌تر به نظر برسد. اصول از پروژه آریا (بازنویسی
`TWF 4.28`) به ارث رسیده و با شرایط این پورتال تنظیم شده‌اند.

---

## اصل ۱ — همان زبان، همان پلتفرم

پورتال با **C# / ASP.NET MVC 5 روی .NET Framework 4.7.2** نوشته می‌شود: همان چیزی که
نسخه قدیمی روی آن اجرا می‌شد.

* سرور ویندوز مشتری از قبل IIS و .NET 4.7.2 دارد؛ مهاجرت نباید به نصب runtime جدید وابسته باشد.
* موتور (`Personnel.dll`, `T5V3.DB.dll`, `T5V3.Attendance.dll`, `T5V3.LeaveCalcs.dll`)
  فقط و فقط روی .NET Framework قابل بارگذاری است. نسخه‌ای که موتور را صدا بزند و
  روی .NET جدید نوشته شده باشد، اصلاً بالا نمی‌آید.
* هیچ بسته NuGet جدیدی اضافه نمی‌شود؛ تنها DLLهای موجود در `bin` نسخه قدیمی استفاده می‌شوند
  (Dapper، System.Web.Mvc). شبکه مشتری آفلاین است و بازگردانی بسته از اینترنت ممکن نیست.

**سنجش:** `<TargetFrameworkVersion>v4.7.2</TargetFrameworkVersion>` در هر چهار پروژه،
و `lib/` بدون هیچ ارجاع خارج از `bin` نسخه قدیمی.

## اصل ۲ — صفر قفل، صفر لایسنس، صفر تماس بیرونی

قفل سخت‌افزاری و هر سازوکار لایسنس به‌طور موقت حذف شده‌اند تا تصمیم تیم مدیریت درباره
نحوه قفل‌گذاری آینده روشن شود. این یعنی:

| ممنوع | چرا |
| :-- | :-- |
| `TINYLib` و `Interop.TINYLib` | قفل سخت‌افزاری/دانگل؛ روی سرور بدون دانگل، شکننده و غیرقابل‌آزمون است |
| `T5V3.ZK.DLL`, `Push.dll`, `Sensor.dll` | وابستگی native و ۳۲-بیتی؛ IIS 64-بیتی نمی‌تواند بارگذاری کند |
| هر فراخوانی `HttpClient`/`WebRequest`/`WebClient` | شبکه مشتری به اینترنت وصل نیست؛ تماس بیرونی = انتظار تا timeout |
| «فعال‌سازی آنلاین»، تلمتری، بررسی به‌روزرسانی | همان دلیل بالا |
| حساب `sa` یا کاربر DB با حق DDL | پورتال با یک لاگین کم‌دسترسی به جداول خودش محدود می‌شود |

**سنجش:** `T12` تمام فایل‌های `.cs`، `.cshtml` و `.config` را برای این واژه‌ها اسکن می‌کند.
اسکریپت `db/02-t5web-sql-login.sql` کاربر `t5web_admin` را با کمترین دسترسی می‌سازد و
`DENY UPDATE, DELETE` روی جدول حسابرسی می‌گذارد.

## اصل ۳ — ۱۰۰٪ آفلاین در رابط کاربری

هیچ چیزی در مرورگر از بیرون بارگذاری نمی‌شود: نه CDN، نه فونت وب (Google Fonts/Vazir از
اینترنت)، نه آیکون‌فونت (FontAwesome)، نه نقشه، نه اسکریپت تحلیلی.

* CSS و JS دست‌نویس و درون مخزن: `T5Web.Web/Content/t5web-admin.css` و `t5web-admin.js`.
* فونت: پشته فونت سیستم (`Segoe UI`, `Tahoma`, `Iranian Sans` اگر نصب باشد) — بدون `@font-face` بیرونی.
* آیکون: نویسه‌های متنی/اشکال CSS، یا `<span aria-hidden>`؛ هیچ فایل فونت آیکون.
* CSP سخت‌گیرانه: `default-src 'self'`، `script-src 'self'`، بدون `unsafe-inline`.
  هر اسکریپت یا استایل درون‌خطی مسدود می‌شود — به همین دلیل `onchange="…"` در نماها ممنوع است
  و رفتار از طریق `data-*` و یک فایل JS انجام می‌شود (`BUG-10`).

**سنجش:** `T09` (نبود `http://`/`https://`/`//cdn` و `@font-face` با URL بیرونی) و `T10` (نبود
`onclick`/`onchange`/`style="…"` درون‌خطی و `@helper`).

## اصل ۴ — لایه‌بندی صریح، وابستگی یک‌طرفه

```
T5Web.Domain          مدل‌ها، enumها، قراردادها        (بدون وابستگی)
      ▲
T5Web.Application     منطق کاری: چارت، گردش کار، دسترسی (فقط Domain)
      ▲
T5Web.Data            Dapper + دایرکتوری موتور + مخزن حافظه‌ای
      ▲
T5Web.Web             کنترلرها، نماها، امنیت، پیکربندی
```

قواعد:

1. `Domain` به هیچ‌چیز وابسته نیست — نه به `System.Web`، نه به Dapper.
2. `Application` به `System.Web` دسترسی ندارد؛ اگر خدمتی به `HttpContext` نیاز داشت،
   یعنی طراحی اشتباه است و باید ورودی از کنترلر پاس شود.
3. `Data` تنها لایه‌ای است که SQL یا `Personnel.DB` را می‌شناسد.
4. نماها هیچ‌گاه SQL یا `Personnel` را صدا نمی‌زنند؛ فقط مدل آماده نمایش می‌گیرند.
5. `T5Web.Tests` می‌تواند به همه لایه‌ها نگاه کند — آزمون، مصرف‌کننده است نه جزء معماری.

**سنجش:** مرور `.csproj`ها (هر پروژه فقط به لایه پایین‌تر ارجاع دارد) + `lint-csharp.py`
(ممنوعیت `System.Web` در Application و `SqlConnection` در Web).

## اصل ۵ — وابستگی سخت به موتور T5، ولی فقط در داده

سازمان، سلسله‌مراتب و سطوح دسترسی از موتور T5 می‌آید؛ پورتال **مالک** آن‌ها نیست:

* خواندن ساختار سازمانی و پیکربندی دستگاه‌ها از لایه DA خود موتور
  (`Personnel.DB.DepartmentDA`, `TitleChartDA`, `EmpTypeDA`, `DeviceDA`) انجام می‌شود،
  تا پورتال هرگز مجبور نباشد اسکیمای موتور را دوباره در SQL بنویسد.
* نوشتن در جداول موتور از مسیر SQL انجام می‌شود، چون `AddNew/Edit/Delete` موتور به یک
  `DBManager` نمونه-سراسری وابسته‌اند که در فرایند وب قابل اشتراک نیست.
* پورتال فقط دو جدول از خودش دارد: `[T5WebAccess]` و `[T5WebAudit]`. هیچ جدول موتور،
  هیچ ستون موتور و هیچ رویه ذخیره‌شده‌ای تغییر نمی‌کند.
* نسخه موتور قفل است (`engine/engine-pin.json`). اگر DLL موتور عوض شود،
  `verify-engine-pin.py --check` قرمز می‌شود و بیلد متوقف می‌شود.

**سنجش:** `T11` (گیت‌های بیلد)، `T14` (قرارداد مدل موتور)، `verify-sql-schema.py`.

## اصل ۶ — ظاهر صنعتی و دست‌ساز، نه پیش‌فرض‌های AI

رابط کاربری باید شبیه یک ابزار عملیاتی جدی باشد، نه یک قالب آماده:

* پالت: کاغذ گرم `#f4f2ec`، فولاد تیره `#26333f`، فیروزه‌ای داده `#0f7a76`.
  بدون گرادیان تزئینی، بدون سایه‌های رنگی، بدون کارت‌های گرد ۱۶ پیکسلی.
* تایپوگرافی فشرده و راست‌به‌چپ واقعی؛ اعداد لاتین در ستون‌های عددی برای هم‌ترازی.
* چیدمان جدول-محور با خطوط مویی و بدون «قهرمان صفحه» تزئینی؛ رنگ فقط برای داده مصرف می‌شود
  (سبز/سرخ برای وضعیت، نه برای تزئین).
* بدون ایموجی، بدون آیکون اینترنتی، بدون انیمیشن چرخشی، بدون متن انگلیسی تزئینی.
* دسترس‌پذیری: کنتراست ≥ 4.5:1، `:focus-visible` واضح، همه فرم‌ها با `label`.

**سنجش:** `T09`/`T10` برای نبود منابع بیرونی و اسکریپت درون‌خطی، و بازبینی چشمی
`preview/` که با همان `t5web-admin.css` ساخته شده است.

## معیار پذیرش کل پروژه

بازنویسی زمانی کامل است که **همه‌ی** موارد زیر برقرار باشند:

1. هر ۶۷ کنترلر و ۳۴۳ کنش عمومی نسخه قدیمی در `docs/legacy-controllers.txt` معادل مشخصی داشته باشد (`T13`, `T25`, `T27`) و سطح فایل (نماها، اسمبلی‌ها، کلیدهای پیکربندی) هم پوشش داده شود (`T29`).
2. `build-and-test.sh` (بدون `--gates`) روی ویندوز سبز باشد: چهار گیت + همه آزمون‌ها.
3. هیچ عیب بازِ بدون آزمون در `docs/04-bugs.md` نمانده باشد.
4. `preview/` و پورتال واقعی از یک فایل CSS تغذیه شوند (`t5web-admin.css`).
5. راهنمای نصب/بازگردانی (`docs/08-runbook.md`) برای تیم عملیات وجود داشته باشد.

## اصل ۷ — دو کاتالوگ، یک دستور

اسکیمای T5 روی **دو** پایگاه تقسیم شده است: `ReportT5V3` (تردد، درخواست، مرخصی، شیفت، گردش
کار) و `Personnel` (افراد، سازمان، عناوین، دستگاه‌ها). نسخه قدیمی جدول‌های این دو را در یک
`JOIN` می‌آورد؛ این فقط روی سروری کار می‌کند که هر دو پایگاه را دارد و لاگین به هر دو دسترسی
داشته باشد.

* هر دستور SQL فقط **یک** کاتالوگ را لمس می‌کند؛
* ستون‌های نمایشی از کاتالوگ دوم با `PersonnelDirectory` خوانده و در حافظه وصل می‌شوند؛
* مدل (کلیدها و رابطه‌ها) از شاهد تولید و در `engine/relations.{json,tsv}` قفل می‌شود؛
* گیت `tools/engine-relations.py --check` و آزمون `T28` هر تخطی را در بیلد می‌گیرند.

جزئیات: `docs/09-database-model.md`.
