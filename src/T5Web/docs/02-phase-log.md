# ۰۲ — گزارش فازها (Phase Log)

این سند تاریخچه اجرای فازها را نگه می‌دارد: در هر فاز چه ساخته شد، چه عیبی پیدا شد،
چه آزمونی اضافه شد، و چه چیزی باقی ماند. **این سند گذشته است؛ وضعیت جاری در
`docs/phase-status.csv` و برنامه آینده در `docs/06-phase-plan.md` است.**

قاعده: هر سطر این سند باید یا به یک فایل موجود اشاره کند یا به یک آزمون با شناسه مشخص.
اگر چیزی ساخته شد و بعد حذف شد، سطرش می‌مانَد و دلیلش نوشته می‌شود — تاریخ را بازنویسی نمی‌کنیم.

### ۶-ح. موج ۲ و ۳ شکاف T5V3 (فاز ۷)

۲۱ ماژول عمومی تازه (`position`…`userbiodata`)، خوانندهٔ سه لاگ (`LogsController` با
منابع `SystemLog`/`OperationLog`/`DownloadRecordsLog`)، و صفحهٔ «سلامت داده»
(`IntegrityController` با هفت بررسی رابطهٔ منطقی) اضافه شد. فهرست نوع ستون‌ها از ۴۶ به
۷۵ جدول رسید و `T32` کل این سطح را می‌سنجد.

**باگی که همین موج پیدا و رفع کرد:** عنوان فارسی `AdminFeature.PersonnelPhoto` دو بار در
دیکشنری `TitlesFa` آمده بود؛ چون دیکشنری در سازندهٔ ثابت ساخته می‌شود، اولین استفاده
`ArgumentException` می‌داد و کل کنسول از کار می‌افتاد. `T32` حالا یگانگی کلیدها و وجود
عنوان برای همهٔ اعضای `AdminFeature` را می‌سنجد.

### ۶-ز. موج ۱ شکاف T5V3 (فاز ۶)

تحلیل شکاف با دسکتاپ (`docs/10`) نشان داد ۱۱ قابلیت T5V3 در پورتال معادل ندارند. موج ۱
چهار موردِ کم‌ریسک را اضافه کرد: آرشیو تصاویر پرسنل، سهمیهٔ مرخصی نوع استخدام، توضیحات
مرخصی (ماژول عمومی) و گزارش «لیست مرخصی‌ها». `T31` هر چهار مورد را می‌سنجد.

یک موردِ برنامه‌ریزی‌شده عمداً اضافه **نشد**: «ساعات کار هفتگی». جدول `[TimeTable]` بر
اساس `engine/relations.json` در کاتالوگ سرویس دستگاه است و قاعدهٔ «پورتال به آن کاتالوگ
وصل نمی‌شود» (همان که ماژول `option` را حذف کرد) اجازه نمی‌دهد روی `T5CnnStr` نوشته شود.
این تصمیم در `docs/10` §۵ ثبت شده است.

### ۶-الف. کلیدهای پیکربندی نسخه قدیمی، یکی‌یکی

پوشش کنترلر/کنش کافی نیست: بعضی قابلیت‌ها در `Web.config` بودند، نه در کد. هر کلید
`appSettings` نسخه ۳.۵.۷ بررسی شد:

| کلید قدیمی | تصمیم در بازنویسی |
| :-- | :-- |
| `Link5ServiceURL` (`http://127.0.0.1:15222/Device/`) | **جایگزین شد**: صف واقعی `[T5WebDeviceCommand]` به‌جای فراخوانی HTTP (`BUG-26`، `docs/08` بند ۵-الف) |
| `t5ConnectionString` / `personnelConnectionString` (قالب EF) | همان دو پایگاه (ReportT5V3 و Personnel) با کلیدهای `T5CnnStr` / `PersonnelCnnStr`؛ قالب EF هم پذیرفته می‌شود (`MvcApplication`) |

### ۶-ج. پایگاه‌داده: مدل، کاتالوگ‌ها و رابطه‌ها

پرسش «دیتابیس پیاده شده؟» یک جواب درست داشت: **نه، فقط جدول‌ها شناخته شده بودند، نه رابطه‌ها**.
تا این مرحله هیچ‌جای پروژه نمی‌دانست کدام جدول در کدام کاتالوگ است و کدام ستون به کدام جدول
اشاره می‌کند؛ `db/schema-manifest.json` فقط نام جدول و ستون داشت.

| کار | خروجی |
| :-- | :-- |
| استخراج DDL واقعی (۳۰ + ۴۶ جدول) با `PRIMARY KEY` و **۳۳ `FOREIGN KEY`** | `tools/engine-relations.py` → `engine/relations.json` |
| انتساب هر ۱۳۰ جدول به یک کاتالوگ (با شاهد) | ۵۴ موتور · ۳۳ پرسنل · ۴۰ سرویس دستگاه · ۳ جدول پورتال |
| حل هر ستون ارجاعی به مقصدش | ۳۳ `declared` + ۶۰ `inferred` = **۹۳ رابطه**؛ ۳۱ رابطه بین‌کاتالوگی |
| فهرست استثناها با دلیل | ۹ ستون (enum، شناسه دستگاه، کاربر نرم‌افزار) — ۰ نامعلوم |
| قفل در بیلد | گیت هشتم `engine-relations.py --check` + آزمون `T28` |
| رفع شکاف واقعی | `BUG-28`: دو کاتالوگ در یک اتصال؛ `BUG-29`: دو «جدول» ناموجود در manifest |
| بازنویسی لایه داده | `PersonnelDirectory` + دو کارخانه‌ی اتصال در ۴ مخزن؛ هیچ `JOIN` بین‌کاتالوگی نمانده |
| گزارش سلامت روی داده واقعی | `db/03-relations.sql` (فقط-خواندنی، ۲۰ بررسی + `Verdict`) |
| آداپتر موتور و ماژول‌ها | `BUG-30`: `PersonnelEngineDirectory` و `SqlModuleStore` هم باید کاتالوگ خودشان را باز کنند؛ هر ماژول حالا `Catalog` دارد و `T16` آن را با مدل می‌سنجد |
| ماژول نامربوط حذف شد | ماژول `option` روی جدول `Option` (کاتالوگ سرویس دستگاه) بود؛ نه `ParametersController` قدیمی از آن استفاده می‌کرد (آن `ParameterDA` بود) و نه پورتال اجازه نوشتن در آن کاتالوگ را دارد → حذف شد (۳۰ → ۲۹ ماژول) |
| گیت دولایه | سطح دستور (یک دستور، یک کاتالوگ) + سطح متد (دستور `Personnel` فقط با `OpenPersonnel`)؛ دو نقص واقعی را همین لایهٔ دوم پیدا کرد: `GetTableCounts` و `CountMembersByDepartment` (`BUG-30`) |
| سند | `docs/09-database-model.md` (اصل ۷ در `docs/01`) |
