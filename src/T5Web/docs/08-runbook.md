# ۰۸ — Runbook نصب، راه‌اندازی و بازگردانی

این سند برای تیم عملیات نوشته شده است، نه برای برنامه‌نویس. هر گام یا یک فرمان است یا یک
کار در IIS؛ هیچ‌جا «بعداً مستند می‌شود» وجود ندارد.

> **دو اصل حاکم بر این سند**
> ۱. شبکه **کاملاً آفلاین** است: هیچ گام نصب به اینترنت نیاز ندارد و هیچ بسته‌ای از NuGet دانلود نمی‌شود.
> ۲. هیچ قفل سخت‌افزاری و هیچ فایل لایسنسی وجود ندارد (اصل ۲ در `docs/01`). اگر جایی
>    از شما «سریال» یا «فایل قفل» خواسته شد، آن سند متعلق به نسخه قدیمی است.

---

## ۱. پیش‌نیازها

| مورد | مقدار | بررسی |
| :-- | :-- | :-- |
| ویندوز | Server 2016 یا بالاتر | `winver` |
| IIS | با نقش‌های `ASP.NET 4.8`، `Windows Authentication`، `URL Rewrite` (اختیاری) | `Get-WindowsFeature Web-Asp-Net45, Web-Windows-Auth` |
| .NET Framework | 4.7.2 یا بالاتر | `reg query "HKLM\SOFTWARE\Microsoft\NET Framework Setup\NDP\v4\Full" /v Release` |
| SQL Server | 2016 یا بالاتر، با پایگاه‌های `ReportT5V3` و `Personnel` | `sqlcmd -Q "SELECT name FROM sys.databases"` |
| حساب سرویس | حساب ویندوزی دامنه‌ای با دسترسی `db_datareader`/`db_datawriter` به دو پایگاه + `EXECUTE` روی اسکیمای `dbo` | بخش ۳ |

**چیزی که لازم نیست:** Office/Excel، کارت گرافیک، قفل USB، `TINYLib`، اینترنت.

## ۲. نصب (۱۵ دقیقه)

1. پوشه انتشار را در `C:\inetpub\T5WebAdmin` کپی کنید (خروجی `msbuild T5Web.sln /p:Configuration=Release`).
2. در IIS یک Application Pool بسازید: **.NET CLR v4.0**، **Integrated**، **No Managed Code = False**،
   و در *Advanced Settings* گزینه **Load User Profile = True** (لازم برای احراز هویت ویندوزی).
3. Identity همان حساب سرویس بخش ۱ باشد، نه `ApplicationPoolIdentity`.
4. سایت را روی پورت دلخواه (مثلاً `8081`) با **Windows Authentication = Enabled** و
   **Anonymous = Disabled** ببندید.
5. اسکریپت‌های پایگاه‌داده را با حساب `sysadmin` یک‌بار اجرا کنید:

```sql
-- به ترتیب
:r .\db\01-t5web-objects.sql
:r .\db\02-t5web-sql-login.sql
-- سپس بررسی
:r .\db\verify.sql
-- و اختیاری ولی توصیه‌شده: سلامت رابطه‌ها روی داده واقعی (docs/09)
:r .\db\03-relations.sql
```

`verify.sql` باید **هیچ** سطر `MISSING` برنگرداند. اگر برگرداند، نصب کامل نیست؛ به بخش ۶ بروید.

6. `Web.config` را برای محیط تنظیم کنید:

```xml
<appSettings>
  <!-- کاتالوگ موتور: تردد، درخواست، مرخصی، شیفت، گردش کار -->
  <add key="T5CnnStr" value="data source=SQL01;initial catalog=ReportT5V3;integrated security=True;MultipleActiveResultSets=True" />
  <!-- کاتالوگ پرسنل: افراد، سازمان، عناوین، دستگاه‌ها (docs/09) -->
  <add key="PersonnelCnnStr" value="data source=SQL01;initial catalog=Personnel;integrated security=True;MultipleActiveResultSets=True" />
  <add key="T5WebMode" value="coexist" />
  <add key="T5WebLegacyUrl" value="http://legacy-web/" />
</appSettings>
```

7. نخستین بازدید: `http://<server>:8081/Diagnostics`. این صفحه وضعیت اتصال، تعداد جداول،
   حالت هم‌زیستی و آخرین رخداد حسابرسی را نشان می‌دهد. تا وقتی این صفحه سبز نیست،
   هیچ‌کس نباید از پورتال استفاده کند.

## ۳. مجوزهای پایگاه‌داده (کمترین امتیاز)

```sql
USE [ReportT5V3];
CREATE USER [DOMAIN\svc-t5web] FOR LOGIN [DOMAIN\svc-t5web];
ALTER ROLE db_datareader ADD MEMBER [DOMAIN\svc-t5web];
ALTER ROLE db_datawriter ADD MEMBER [DOMAIN\svc-t5web];
GRANT EXECUTE ON SCHEMA::dbo TO [DOMAIN\svc-t5web];
-- هیچ‌گاه db_owner یا sysadmin ندهید.
```

پورتال **DDL اجرا نمی‌کند**؛ ساختار در `db/01-t5web-objects.sql` است و فقط در نصب/ارتقا اجرا می‌شود.

## ۴. کلید تغییر فاز (Coexistence Switch)

نسخه قبلی و پورتال **هم‌زمان** روی یک پایگاه‌داده کار می‌کنند. یک `appSetting` مشخص می‌کند
کدام‌یک مرجع است؛ هر تغییر فقط یک بازنشانی Application Pool لازم دارد (بدون نصب دوباره).

| `T5WebMode` | رفتار پورتال | چه زمانی |
| :-- | :-- | :-- |
| `coexist` (پیش‌فرض) | همه صفحه‌ها فعال، یک نوار زرد بالای هر صفحه: «حالت هم‌زیستی» + پیوند به نسخه قبلی | هفته‌های آزمایش موازی |
| `portal` | پورتال مرجع است، نوار حذف می‌شود | پس از پذیرش عملیاتی |
| `legacy` | پورتال نصب است ولی وصله وضعیت قرمز نشان می‌دهد که مرجع، نسخه قبلی است | هنگام بازگردانی |

`T5WebLegacyUrl` آدرس نسخه قبلی است؛ در حالت `coexist` به‌صورت پیوند «رفتن به نسخه قبلی»
در نوار کناری و در حالت `legacy` به‌عنوان مقصد بازگردانی استفاده می‌شود.

**کلید خاموش‌کردن یک ماژول (بدون خاموش‌کردن پورتال):**

```xml
<add key="ModuleEnabled:parameter" value="false" />
```

هر ماژول عمومی یک کلید `ModuleEnabled:<code>` دارد؛ نبودِ کلید یعنی «فعال». ماژول خاموش،
مثل ماژول ناموجود رفتار می‌کند (۴۰۴)، پس حتی با حدس آدرس هم باز نمی‌شود.

**قاعده طلایی:** در حالت `coexist` هر رکوردی را فقط در **یک** برنامه ویرایش کنید. پورتال و
نسخه قبلی هیچ قفلی روی رکورد نمی‌گذارند؛ دو ویرایش هم‌زمان، آخرین نوشته را برنده می‌کند.

## ۵. چک‌لیست روز اول

- [ ] `/Diagnostics` سبز است (اتصال، شمارش جداول، حالت هم‌زیستی).
- [ ] ورود با یک حساب عادی انجام شد و منو **فقط** قابلیت‌های مجاز را نشان داد.
- [ ] ورود با حسابی که هیچ قابلیتی ندارد: صفحه «دسترسی ندارید» با کد ۴۰۳ (نه خطای زرد).
- [ ] یک تردد در «ترددها» اصلاح شد و بلافاصله در «رخدادها» با دلیل دیده شد.
- [ ] یک درخواست با عنوان شغلی فعال تأیید شد؛ تأیید دوم با همان عنوان رد شد.
- [ ] یک خروجی CSV از «گزارش‌ها» گرفته شد و در Excel با کدگذاری UTF-8 باز شد.
- [ ] «انتقال مانده سال» فقط پیش‌نمایش گرفته شد (اجرای واقعی در روز مقرر).
- [ ] نسخه پشتیبان پایگاه‌داده **پیش از** هر انتقال یا ورود گروهی گرفته شده است.

## ۵-الف. صف دستور دستگاه (قرارداد با سرویس دسکتاپ)

نسخه قدیمی دستور دستگاه را با یک فراخوانی HTTP به `Link5ServiceURL`
(`http://127.0.0.1:15222/Device/`) تحویل می‌داد. پورتال جدید این کار را نمی‌کند — یک
برنامه وب که سوکت سخت‌افزار را در دست بگیرد، نه آفلاین آزمون‌پذیر است و نه از ری‌استارت
سرویس جان سالم به در می‌برد. جای آن:

1. اپراتور در `/Device` یکی از پنج دستور بسته را انتخاب می‌کند؛
2. پورتال یک سطر در `[T5WebDeviceCommand]` می‌نویسد (`Status = 0`) و یک سطر حسابرسی
   با `ticket=<ID>` ثبت می‌کند؛
3. **سرویس دسکتاپ** (همان سرویسی که سوکت دستگاه‌ها را دارد) صف را می‌خواند:

```sql
-- برداشتن دستور بعدی (اتمیک، چند مصرف‌کننده بی‌خطر)
UPDATE TOP (1) dbo.T5WebDeviceCommand
SET Status = 1                       -- 1 = taken
OUTPUT INSERTED.ID, INSERTED.MachineNumber, INSERTED.Command
WHERE Status = 0;
```

4. پس از اجرا، `Status = 2` (انجام شد) یا `3` (ناموفق) و توضیح در `Note` نوشته می‌شود.
   پورتال این سطرها را در پایین همان صفحه نشان می‌دهد و هرگز وضعیت را از خود نمی‌سازد.

**قاعده:** پورتال هرگز منتظر پاسخ دستگاه نمی‌ماند و هیچ درخواست بیرونی نمی‌فرستد
(`T12`)؛ اگر سرویس دسکتاپ خاموش باشد، صف فقط پر می‌شود و همین، نشانه عیب است.

## ۶. خطاهای رایج و درمان

| نشانه | علت | درمان |
| :-- | :-- | :-- |
| صفحه «پیکربندی ناقص» | `T5CnnStr` خالی یا نامعتبر | `Web.config` را اصلاح و Application Pool را ری‌استارت کنید |
| خطای ۴۰۱ برای همه | Anonymous روشن و Windows Authentication خاموش | تنظیمات Authentication سایت را درست کنید |
| `MISSING` در `verify.sql` | اجرای ناقص `db/01` | اسکریپت را دوباره و کامل اجرا کنید |
| صفحه «پیکربندی ناقص» با پیام `PersonnelCnnStr` | کلید دوم کاتالوگ تنظیم نشده | اگر همه‌ی جدول‌ها در `ReportT5V3` هستند، خالی بگذارید (پورتال تک‌پایگاهی کار می‌کند)؛ در غیر این صورت مقدار بدهید (docs/09) |
| `Invalid object name 'UserInfo'` | `PersonnelCnnStr` به پایگاه اشتباه اشاره می‌کند یا خالی است و جدول‌ها در `ReportT5V3` نیستند | مقدار درست را بگذارید؛ `db/03-relations.sql` را اجرا کنید |
| «مخزن … تنظیم نشده است» | یکی از storeها در `MvcApplication` ساخته نشده | نسخه انتشار را کامل کپی کنید (فایل‌های `T5Web.Data` جا افتاده‌اند) |
| «عنوان شغلی فعال ندارید» در تأیید درخواست | پرسنل در `UserInfoTitles` سطر فعال ندارد | در برنامه دسکتاپ عنوان را ثبت کنید؛ پورتال عمداً هیچ عنوانی حدس نمی‌زند |
| گزارش «موتور حضور» عدد محاسبه‌شده نشان نمی‌دهد | این گزارش‌ها را موتور رندر می‌کند، نه پورتال | همان قالب RDLC را در برنامه دسکتاپ اجرا کنید؛ پورتال فقط «تردد خام» می‌دهد |
| ورود CSV همه سطرها را رد می‌کند | فایل با کدگذاری قدیمی ذخیره شده | در Excel با «CSV UTF-8» ذخیره کنید (سرستون‌ها در صفحه فهرست شده‌اند) |
| دستور دستگاه در صف می‌ماند | سرویس دسکتاپ اجرا نیست یا `[T5WebDeviceCommand]` را نمی‌خواند | سرویس را اجرا کنید؛ سطرهای `Status = 0` عمداً پاک نمی‌شوند (اثر انگشت کار انجام‌نشده) |
| «انتقال این سال قبلاً انجام شده است» | محافظ تکرار | درست است؛ برای اصلاح، سطرهای `LeavesAdded` با شرح «انتقال مانده» را با نظر مالی بررسی کنید |

## ۷. پشتیبان‌گیری و بازگردانی

**پیش از** هر عملیات گروهی (انتقال مانده سال، ورود CSV، تغییر زنجیره تأیید):

```sql
BACKUP DATABASE [ReportT5V3] TO DISK = N'D:\backup\ReportT5V3-before-cutover.bak' WITH COMPRESSION, INIT;
BACKUP DATABASE [Personnel] TO DISK = N'D:\backup\Personnel-before-cutover.bak' WITH COMPRESSION, INIT;
```

**بازگردانی کامل (rollback):**

1. `T5WebMode` را روی `legacy` بگذارید و Application Pool را ری‌استارت کنید (۳۰ ثانیه).
2. اگر داده هم باید برگردد: پایگاه‌داده را از فایل بالا `RESTORE` کنید — **این کار نسخه قبلی را هم
   به همان لحظه برمی‌گرداند**، چون هر دو یک پایگاه‌داده دارند. پس پیش از بازگردانی، رخدادهای
   پورتال را از `/Audit` خروجی بگیرید تا سابقه از دست نرود.
3. پس از پایدارشدن، `/Diagnostics` را دوباره بررسی کنید.

**آزمون بازگردانی** باید یک‌بار روی سرور آزمایشی انجام شده باشد؛ بازگردانی‌ای که آزمون نشده،
بازگردانی نیست.

## ۹. ارتقای موتور (Pin)

`engine/engine-pin.json` نسخه‌ای را که پورتال روی آن آزمون شده نگه می‌دارد. پس از هر ارتقای
`Personnel.dll` / `T5V3.DB.dll`:

```bash
./build-and-test.sh --gates          # pin + manifest + SQL + C# + model contract
python3 tools/engine-column-types.py # نوع ستون‌ها را از DDL تازه بازتولید می‌کند
```

اگر گیت شکست، ارتقا **انجام نشده** است؛ ابتدا تفاوت امضاها را در `engine/model-contract.json`
ببینید (این همان روشی است که در آریا `BUG-01`…`BUG-07` را قبل از تولید پیدا کرد).
