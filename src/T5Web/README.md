# آریا ادمین (Aria Admin) — بازنویسی مستقل پورتال مدیریت T5Web

**نام ثبت‌شده محصول:** «آریا ادمین» · **کد محصول:** `ARIA-ADMIN` · **نسخه:** `Aria Admin v5.0`
**مبنا:** بازنویسی `T5Web [3.5.7]` (`T5V3Web.dll` — ۶۷ کنترلر / ۳۴۳ کنش) روی MVC 5 / .NET 4.7.2.

پورتال مدیریت سازمانی، بازنویسی‌شده از `T5Web [3.5.7]` (MVC 5 / .NET 4.7.2).
این پروژه **مستقل** از آریا است؛ تنها اشتراکش با آریا، پایگاه‌داده T5 است.
نام پوشه (`src/T5Web`) یک مسیر است، نه نام محصول؛ هویت محصول در
`T5Web.Web/Content/AriaAdminBranding.cs` نگه‌داری می‌شود و `T30` آن را می‌سنجد.

| مورد | مقدار |
|---|---|
| نام محصول | «آریا ادمین» (`ARIA-ADMIN`) — همان‌طور که بازنویسی TWF با نام «آریا» ثبت شد |
| پلتفرم | .NET Framework 4.7.2 · ASP.NET MVC 5 |
| احراز هویت | Windows/Negotiate (بدون فرم رمز، بدون ذخیره رمز در پورتال) |
| مجوزدهی | بر پایه قابلیت (`AdminFeature`) — پیش‌فرض ممنوع، «ممنوع» همیشه برنده |
| موتور | همان بیلد قفل‌شده آریا: `t5web-3.5.7` (`../TWF/engine/engine-pin.json`) |
| رابط کاربری | ۱۰۰٪ آفلاین، RTL، بدون CDN/فونت وب/Kendo/jQuery |
| حسابرسی | دفتر رخداد فقط-افزودنی با زنجیره هش SHA-256 |

## اجرای بررسی‌ها

```bash
./build-and-test.sh --gates     # فقط گیت‌های استاتیک (بدون کامپایلر هم کار می‌کند)
./build-and-test.sh             # گیت‌ها + کامپایل + اجرای آزمون‌ها
```

گیت‌های استاتیک (همان ابزارهای آریا، چون هر دو یک اسکیما و یک موتور دارند):

1. `verify-engine-pin.py --check` — موتور قفل‌شده در دسترس است؛
2. `build-schema-manifest.py --check` — فهرست اسکیما با منابعش هم‌خوان است؛
3. `verify-sql-schema.py` — هیچ SQL دست‌سازی به جدول/ستون ناموجود اشاره نمی‌کند؛
4. `lint-csharp.py` — توازن ساختار، نوع تکراری، فراخوانی API موتور، الگوهای ممنوع؛
5. `tools/engine-model-contract.py --check` — اعضای مدل موتور که پورتال می‌خواند در بیلد قفل‌شده وجود دارند (`T14`)؛
6. `tools/engine-column-types.py --check` — نوع هر ستونی که ماژول‌ها می‌نویسند، از DDL یا ORM اثبات شده است (`T16`)؛
7. `tools/legacy-coverage.py --check` — هر ۳۴۳ کنش عمومی نسخه قدیمی تصمیم ثبت‌شده دارد و هر مقصد در کد وجود دارد (`T27`)؛
8. `tools/engine-relations.py --check` — هر جدول یک کاتالوگ، هر کلید یک شاهد، هر ارجاع یک مقصد دارد؛ هیچ دستوری دو کاتالوگ را با هم نمی‌آمیزد و هیچ دستورِ `Personnel` روی اتصال موتور اجرا نمی‌شود (`T16`، `T28`).

## پیش‌نمایش آفلاین

```bash
python3 preview/server.py       # http://0.0.0.0:8090/preview/
```

پیش‌نمایش از ریشه `src/T5Web` سرو می‌شود، پس همان `T5Web.Web/Content/t5web-admin.css`
و `t5web-admin.js` را بارگذاری می‌کند — هیچ فایلی کپی نمی‌شود و هیچ منبعی از اینترنت نمی‌آید.
`T09` تضمین می‌کند هر صفحه پیش‌نمایش همان استایل محصول را بخواند و استایل/رویداد درون‌خطی نداشته باشد.

## نصب

```text
1) db/01-t5web-objects.sql       (جدول‌های T5WebAccess و T5WebAudit)
2) db/02-t5web-sql-login.sql     (لاگین t5web_admin + مجوزهای حداقلی؛ رمز را عوض کنید)
3) db/verify.sql                 (همه سطرها باید OK باشند)
4) IIS: Application Pool مستقل (64-bit, No Managed Code → Integrated)
        Authentication: Windows Authentication = Enabled، Anonymous = Disabled
5) Web.config: کلید T5CnnStr (قالب ساده یا قالب قدیمی EF پذیرفته می‌شود)
```

## سه تصمیم که از نسخه قبلی فاصله می‌گیرد

1. **بدون فرم ورود.** نسخه قبلی هم Windows Auth داشت؛ ما همان را نگه داشتیم و
   به‌جای جدول رمز اختصاصی، `UserInfo.WebUser` را مرجع می‌دانیم.
2. **دسترسی به‌ازای قابلیت، نه منو.** مدل تخت چهل‌بولی حذف شد؛ هر قابلیت شناسه
   پایدار دارد و در `T5WebAccess` ذخیره می‌شود، پس قابل آزمون و حسابرسی است.
3. **جدول موتور را تغییر نمی‌دهیم.** اسکیمای T5 مال موتور است (R1). پورتال فقط دو
   جدول اختصاصی خودش را می‌سازد و روی جداول موتور تنها از طریق DA موتور می‌نویسد.

## دو چیز که در بازنویسی *عمداً* انجام نشد

* **بازنویسی موتور محاسبات.** `T5V3.Attendance`/`LeaveCalcs` قفل‌شده و مصرف می‌شوند؛
  دو الگوریتم موازی برای «مانده مرخصی» ریسک قانونی است.
* **بازنویسی قفل سخت‌افزاری.** طبق تصمیم مدیریت موقتاً حذف شده و بعداً درباره‌اش تصمیم
  گرفته می‌شود؛ `T12` نگهبان این وضعیت است.

> **ممیزی مقایسه‌ای با آریا (TWF):** `docs/rewrite-audit-aria-vs-t5web.md` در ریشه مخزن — پوشش، تفاوت‌ها و شکاف‌های هر دو بازنویسی در برابر برنامه منبع.
