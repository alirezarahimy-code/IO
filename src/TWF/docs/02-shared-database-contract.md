# قرارداد پایگاه‌داده مشترک — آریا (TWF) ↔ T5Web / T5V3

**تصمیم معماری:** دو برنامه **جدا** می‌مانند. تنها نقطه اشتراک، **SQL Server** است.
هیچ کد، نشست، احراز هویت یا استقرار مشترکی وجود ندارد.

---

## ۱. مدل مالکیت (اصلاح یک فرض مهم)

فرض رایج: «دیتابیس مال T5Web است و TWF به آن وصل می‌شود».
دقیق‌تر: **اسکیمای دیتابیس مال موتور T5 است** (`T5V3.DB.dll` + `T5V3.Model.dll`) و هر دو
برنامه `T5Web` (کنسول مدیریت) و `T5V3` (دسکتاپ) این موتور را حمل می‌کنند. آریا/توف **مصرف‌کننده** است.

چرا این تفاوت مهم است؟ چون اگر تیم فکر کند «DB مال T5Web است»، ممکن است تصور شود ارتقای T5Web
دیتابیس را «در محدوده خودش» عوض می‌کند، در حالی که ارتقای **دسکتاپ T5V3** هم همان دیتابیس را تغییر می‌دهد.
آنچه آریا را ایمن می‌کند **مالکیت نیست، قرارداد + محافظ (guard)** است.

```
                    ┌────────────────────┐
   کارمندان ───────▶│  آریا (TWF)        │──┐
   (همه پرسنل)      │  پرتال خودخدمتی    │  │
                    └────────────────────┘  │        ┌──────────────────┐
                                            ├───────▶│  SQL Server      │
                    ┌────────────────────┐  │        │  ReportT5V3      │
   مدیران ─────────▶│  T5Web             │──┘        │  Personnel       │
   (تعداد محدود)    │  کنسول مدیریت      │           └──────────────────┘
                    └────────────────────┘                    ▲
                                                              │
                    ┌────────────────────┐                    │
   اپراتور ────────▶│  T5V3 (دسکتاپ)     │────────────────────┘
                    │  + دستگاه/دانگل    │
                    └────────────────────┘
```

## ۲. قواعد اجباری

| # | قاعده | دلیل |
| :-- | :--- | :--- |
| **R1** | آریا **هیچ DDL اجرا نمی‌کند** (CREATE/ALTER/DROP TABLE، ایندکس، SP) | اسکیما مال موتور T5 است |
| **R2** | تنها استثنا: جدول‌های متعلق به اپ که در `db/01-app-objects.sql` فهرست شده‌اند (`PassCheckProps`) | مالکیت آریا |
| **R3** | آریا نباید به نصب بودن `T5Web` وابسته باشد — فقط SQL Server | بسته‌بندی مستقل |
| **R4** | حساب SQL آریا **least-privilege** است: بدون `db_owner`، بدون `db_ddladmin`، بدون `sysadmin` | کاهش شعاع آسیب |
| **R5** | نوشتن در جداول مشترک فقط از مسیر قرارداد DA انجام می‌شود، نه SQL پراکنده | یک حقیقت واحد |
| **R6** | نسخه موتور/اسکیما که آریا با آن تست شده، **پین** می‌شود (بخش ۵) | جلوگیری از واگرایی محاسبات |
| **R7** | هیچ SSO/کوکی/نشست مشترکی بین دو برنامه وجود ندارد | مرز امنیتی |
| **R8** | هاست/پورت/Application Pool جداگانه برای هر برنامه | جداسازی فرایند |

## ۳. جدول‌های تحت قرارداد

### الف) آریا می‌خواند و می‌نویسد (از طریق DA)

| جدول | عملیات | نکته |
| :--- | :--- | :--- |
| `Request`, `RequestAccept` | R/W | چرخه درخواست و گردش کار |
| `DailyLeave`, `HourlyLeave`, `Record`, `OverTime`, `LateAccept`, `EarlyAccept`, `RewardAndPenalty` | R/W | پس از آخرین تایید نوشته می‌شود |
| `Deputy`, `PersonnelDeputy` | R/W | دو لایه جانشینی |
| `Area`, `UserPositionData` | R/W | محدوده‌های جغرافیایی و موقعیت |
| `Calendar`, `DepartmentRules`, `LeaveTypes`, `UserRules` | R/W | از طریق لایه `TD5` (Dapper) |
| `Workflow`, `Parameter`, `Schedule`, `YearRemain`, `LeavesAdded`, `ReportAccess` | R/* | خواندن برای تصمیم‌گیری، نوشتن محدود به قرارداد DA |
| `SystemLog` | W | ثبت ممیزی |

### ب) آریا فقط می‌خواند

| جدول | کاربرد |
| :--- | :--- |
| `UserInfo`, `TitlesChart`, `UserInfoTitles`, `Department`, `EmpType` | چارت سازمانی، سمت، سطح دسترسی |
| `Position`, `PositionStep` | قوانین موقعیت مکانی |
| `Report`, `ReportData`, `ReportFilter` | تعریف گزارش‌ها |

### ج) مالکیت آریا (تنها DDL مجاز)

| جدول | کاربرد |
| :--- | :--- |
| `PassCheckProps` (`[ID]`, `[Badge]`, `[LastChangeDate]`) | تاریخچه تغییر کلمه عبور — سیاست «تغییر در اولین ورود» و «چرخش دوره‌ای» |

### د) خارج از دسترس آریا (متعلق به T5Web/T5V3 — دست نزنید)

`Device*`, `Gate`, `Card`, `Permit`, `USBManagement`, `TransferRemainedLeave`, `TempSchedules`,
`Ramezan`, `ImportFromExcel`, `ReportDesign/ReportTablix*`, `TC5`/`Link5` (`AccessControl`, `BlackList`, …)

## ۴. جداسازی استقرار

| مورد | آریا | T5Web |
| :--- | :--- | :--- |
| Application Pool | `AriaPool` (هویت اختصاصی) | `T5WebPool` |
| مسیر/هاست | `http://aria.local/` | `http://t5web.local/` |
| Web.config | مستقل | مستقل |
| احراز هویت | کوکی `mytimeauth` (AES-256 + HMAC، HttpOnly، SameSite=Strict) | Windows Authentication |
| حساب SQL | `aria_app` (least-privilege) | حساب موتور T5 |

> کوکی آریا `Path=/` دارد. چون `T5Web` از Windows Authentication استفاده می‌کند تداخلی رخ نمی‌دهد،
> ولی اگر روزی هر دو روی **یک هاست** سرو شوند، `Path` باید به مسیر مجازی آریا محدود شود.

## ۵. پین کردن نسخه موتور (ریسک اندازه‌گیری‌شده) ⚠️

سه نسخه متفاوت از موتور در مخزن وجود دارد:

```
T5V3.DB.dll            TWF 4.28 : 742eb648…   T5Web 3.5.7 : 019400eb…   دسکتاپ 3.9.2 : b326b369…
T5V3.Attendance.dll    TWF 4.28 : 693ffed2…   T5Web 3.5.7 : 693ffed2…   دسکتاپ 3.9.2 : 927701ee…
```

یعنی:
- موتور محاسبه کارکرد آریا **با T5Web یکی است** ✅
- اما `T5V3.DB.dll` آریا **با هیچ‌کدام یکی نیست** ⚠️
- و دسکتاپ ۳.۹.۲ با هر دو متفاوت است ⚠️

**اقدام لازم:** آریا روی یک نسخه مشخص پین شود (پیشنهاد: همان بسته `T5Web 3.5.7` که کنسول مدیریت و
موتور محاسبه سازمان است) و نسخه در `docs/engine-pin.md` + تست برابری خروجی ثبت شود.
بدون این، ممکن است یک درخواست در پرتال و کنسول، دو مانده مرخصی متفاوت بدهد.

## ۶. محافظ اسکیما (پیشنهاد برای فاز بعد)

در `Application_Start` آریا، یک `SchemaGuard` سبک اجرا شود:

1. وجود جداول/ستون‌های فهرست بخش ۳ را بررسی کند.
2. اگر ناقص بود، **بالا نیاید** و یک صفحه فارسی گویا نشان دهد:
   «اسکیمای پایگاه‌داده با این نسخه آریا سازگار نیست — ستون X در جدول Y یافت نشد».
3. نسخه اسکیما را در `SystemLog` ثبت کند تا ممیزی ممکن باشد.

این بهتر از خطای پراکنده `Invalid column name` در میانه شیفت است. اسکریپت آمادگی
(`db/verify-schema.sql`) همین بررسی را به‌صورت دستی انجام می‌دهد؛ این guard نسخه خودکار آن است.

## ۸. پیوست — بازنویسی مستقل پورتال T5Web (بندهای R12–R14)

از زمان نوشتن این قرارداد، پورتال مدیریت `T5Web` هم به‌صورت مستقل بازنویسی شد
(`src/T5Web`). این پروژه **همان قرارداد** را رعایت می‌کند، با سه بند افزوده:

| شناسه | قاعده |
| :--- | :--- |
| **R12** | پورتال T5Web فقط دو شیء اختصاصی خودش را می‌سازد: `T5WebAccess` (ماتریس دسترسی) و `T5WebAudit` (دفتر رخداد زنجیره‌ای). هیچ ستونی به جدول‌های موتور اضافه نمی‌کند. |
| **R13** | آریا و پورتال T5Web **هیچ جدول مشترکی جز جدول‌های موتور ندارند**؛ نه کوکی مشترک، نه session مشترک، نه حساب SQL مشترک (`aria_app` در برابر `t5web_admin`). |
| **R14** | هر دو برنامه به یک بیلد موتور مقید هستند (`src/TWF/engine/engine-pin.json`). ارتقای موتور برای یکی و نه دیگری، مجاز نیست. |

جزئیات و نقشه بازنویسی ۶۴ کنترلر قدیمی: `src/T5Web/docs/05-t5web-rewrite-plan.md`.
