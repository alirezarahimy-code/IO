## آزمون‌های تکمیلی مهم

| شناسه | سناریوی پیشنهادی | انتظار و مرز |
|---|---|---|
| T01 | شناسهٔ خارجی یکسان و کارمند یا زمان متفاوت | تعارض مستقل؛ payload قبلی حفظ شود. `M-2030` و `M-2126`. |
| T02 | خطای SQL نامرتبط با duplicate key | خطا منتشر/ثبت امن شود، نه اینکه «تکراری» تلقی شود. `M-2032`, `M-2138`. |
| T03 | منبع فاقد شناسهٔ قابل اعتماد یا زمان نامعتبر | اطلاعات لازم برای بررسی حفظ شود؛ سیاست تکرارزدایی منبع قبل از اعمال تعیین شود. |
| T04 | تغییر شخص از واحد A به B در تاریخ مرزی | نتیجه در هر تاریخ مطابق سیاست انتساب باشد؛ دو نوشتن هم‌زمان قیود را دور نزنند. |
| T05 | مدیر محدود شناسهٔ کارمند، فایل گزارش یا دستگاه بیرون حوزه را حدس بزند | API و فایل از داده محافظت کنند؛ صرف مخفی‌بودن منو کافی نیست. |
| T06 | نقش اصلی/محدود و سرویس دستگاه | مدیر اصلی به اختیارات مصوب دسترسی دارد؛ مدیر محدود و سرویس فقط مجوز اعطایی دارند. |
| T07 | تعدد نقش‌ها و پایان اعتبار جانشینی | پس از پایان بازه یا غیرفعال‌شدن حساب، تصمیم مجاز نباشد و تاریخچه بماند. |
| T08 | تغییر قاعده یا تقویم برای گذشته | نتیجهٔ قبلی بی‌صدا تغییر نکند؛ محاسبهٔ تازه و تصمیم مجاز تاریخچه داشته باشند. |
| T09 | مرخصی/مأموریت/اضافه‌کاری متعارض یا مانده ناکافی | طبق سیاست تأییدشده رد/هشدار داده شود؛ هیچ فرمول حدسی اعلام نشود. |
| T10 | قطع دستگاه وسط انتقال و بازیابی | وضعیت ناقص قابل تشخیص، retry کنترل‌شده، عدم از دست رفتن/تکرار نامعتبر رخداد. |
| T11 | رخداد دسترسی فیزیکی مجاز یا نامجاز | بدون قاعدهٔ مصوب به حضور کاری تبدیل نشود؛ اطلاعات امنیتی فقط برای افراد مجاز باشد. |
| T12 | فرمان گیت، پاک‌سازی و ریست | صرفاً پس از تصویب دامنه، احراز مجوز و تست ایمنی در شبیه‌ساز/محیط مجاز؛ در فاز ۱ اجرا نمی‌شود. |
| T13 | خرابی و بازیابی | backup روی محیط آزمایشی restore و با اهداف مصوب RPO/RTO مقایسه شود. |

| T15 | رشد داده، صفحه‌بندی و محاسبهٔ دورهٔ بزرگ | به حجم و هدف پاسخ تعیین‌شده توسط مالک محصول وابسته است؛ حد عددی هنوز تعیین نشده. |
| T16 | وضعیت TWF/T5/Link5 در مقابل نسخهٔ جدید | نمونه‌های تأییدشده در محیط مجاز مقایسه شوند؛ تفاوت عمدی و ناسازگاری در دفتر تصمیم ثبت شود. |

## سطح‌های اجرا در آینده

- **واحد:** منطق دامنه و مرز بازه؛ از دیتابیس واقعی نتیجه‌گیری نمی‌شود.
- **یکپارچگی:** SQL Server واقعیِ آزمایشی، محدودیت یکتا، تراکنش و هم‌زمانی؛ provider حافظه‌ای جایگزین این آزمون نیست.
- **امنیت/API و مرورگر:** مجوز، محدوده، فایل، RTL، CSRF و ورودی با دادهٔ مصنوعی.
- **دستگاه:** ابتدا شبیه‌ساز؛ سپس فقط مدل‌های مصوب در آزمایشگاه ایزوله با مجوز. عملکرد سخت‌افزار از نام DLL ثابت نمی‌شود.
- **پایلوت/بازیابی:** با اجازه، داده/افراد مجاز، backup و restore آزموده و معیارهای تأییدشده.

وضعیت فعلی SDK و SQL و اجرای تست در [گزارش فاز](README.md) ثبت شده است.
