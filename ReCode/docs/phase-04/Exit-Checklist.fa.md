# صورت‌جلسهٔ خروج فنی مشروط فاز ۴

**تاریخ:** ۲۰۲۶-۱۱-۰۸

**نتیجه:** شرایط فنی برنامهٔ فاز ۴ برای قابلیت‌های فعلی در محیط آزمایشی برآورده شده و برای مرور ارائه می‌شود. تصمیم‌های کسب‌وکار D09/D10، امنیت تولید و قابلیت‌های حوزه‌های بعدی همچنان بازند. این سند اجازهٔ استقرار یا شروع خودکار فاز ۵ نیست.

| شرط | شاهد و محدودیت |
|---|---|
| حساب و ورود امن پایه | Identity با هش و سیاست رمز، قفل حساب، cookie امن، anti-CSRF، تغییر رمز خود و ابطال stamp؛ [آزمون 42538400752](https://github.com/alirezarahimy-code/IO/actions/runs/42538400752) شامل درخواست‌های موفق/ناموفق و تغییر و ابطال نشست است. پیکربندی نهایی TLS و کلیدها مانده است. |
| مدیر اولیه بدون رمز پیش‌فرض | ابزار ترمینالی مستقل با قفل تراکنش، حسابرسی و عدم echo؛ رمز باید در ترمینال انتخاب شود. رقابت دو سازنده، رمز ضعیف، اجرا با ورودی redirectشده و اجرای دوباره روی دو دیتابیس ساختگی آزموده شدند. |
| نقش، مجوز، محدوده و مدیریت | ایجاد حساب/نقش، فعال و غیرفعال، اعطا و لغو، فهرست محدود و ثبت عملیات در API و فرم آزمایشی؛ حساب تازه تا تغییر رمز اولیه محدود است. همهٔ مدیریت‌ها نیاز به `identity.manage` دارند و manager محدود نمی‌تواند خودش را ارتقا دهد. |
| تست کاربر، مدیر محدود، مدیر اصلی و URL مستقیم | آزمون HTTP واقعی بر HTTPS loopback و SQL: دسترسی خود، مدیر واحد دقیق، مدیر با مجوز سراسری، دستکاری شناسه، رد خارج از محدوده، لغو مجوز و حساب غیرفعال؛ آزمون مرورگر Chromium چند مسیر پایه را نیز طی کرد. فرزندان واحد و تاریخ سازمانی فرض موقت هستند. |

| نتیجهٔ اجرا | build و ۱۵ بررسی کنسولی domain و ۸۰ بررسی نام‌دار SQL/HTTPS/ترمینال/مرورگر، به‌علاوهٔ پیام موفقیت نهایی، در job `128907716595` اجرای بالا موفق شد. استفاده از گواهی خودامضا صرفاً برای تست بود. |
| امنیت و تصمیم‌ها | [محدودیت‌ها و راهنمای عملیات](Identity-and-Operations.fa.md) شامل audit قابل دستکاری، TLS/کلیدها، rate limit توزیع‌شده، MFA و D09/D10 است. آزمون نفوذ مستقل و تست همهٔ مرورگرها انجام نشده است. |

فاز بعد تا مرور این خروج آغاز نشده است. هیچ اتصال به سیستم قدیم، دستگاه، دادهٔ واقعی یا استقرار انجام نشد.
