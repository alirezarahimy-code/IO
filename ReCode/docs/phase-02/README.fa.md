# فاز ۲ — محیط توسعه و معماری اولیه

**وضعیت در ۲۰۲۶-۱۱-۰۸: فاز ۲ از نظر کارها و شرط‌های فنی برنامه تکمیل و گزارش برای مرور ارائه شده است.** build و بررسی دامنه در Arena موفق شدند؛ SQL Server آزمایشی موقت در GitHub Actions با موفقیت آزموده شد. نمونهٔ دائمی یا محلی SQL Server در Arena وجود ندارد و تحلیل و پیاده‌سازی دیتابیس متعلق به فاز ۳ است. کاربر ورود به این فاز را پس از خروج مشروط از فاز ۱ تأیید کرد. [صورت‌جلسهٔ پایان](Exit-Checklist.fa.md).

## ابزار و نتیجهٔ واقعی

| مورد | نتیجه |
|---|---|
| محیط | Debian 12، Linux x86_64. |
| SDK | .NET SDK رسمی `10.0.400`، runtimeهای .NET و ASP.NET Core نسخهٔ `10.0.11`، MSBuild `18.9.6` در محیط Arena نصب شدند. نصب در `$HOME/.local/share/dotnet` و پیوند در `$HOME/.local/bin` است؛ پایداری این مسیر موقت بین sessionها تضمین نیست. |
| Build و بررسی C# | اجرای `tools/phase02-verify.sh`: build حالت Release موفق، صفر هشدار و خطا؛ هر **۱۵ بررسی کنسولی دامنه** موفق. این تست‌ها xUnit یا `dotnet test` نیستند و SQL، امنیت و منطق کامل محصول را پوشش نمی‌دهند. |
| میزبان وب | `IO.Web` از build اجرا و دو درخواست HTTP به `/` و `/health/live` هر دو با پاسخ ۲۰۰ و JSON مورد انتظار تأیید شدند، سپس سرویس متوقف شد. این تست رابط مرورگر، احراز هویت یا امنیت نیست. |
| SQL آزمایشی | در Arena، SQL Server، `sqlcmd`، Docker و Podman پیدا نشدند؛ اسکریپت محلی بدون اتصال مسدود شد. در GitHub Actions کانتینر موقت SQL Server Developer `16.0.4305.5` با `sqlcmd` خود ایمیج راه افتاد؛ پرس‌وجوی `SELECT 1`، دریافت نسخه و حذف کانتینر موفق شدند و در متادیتای اجرای نهایی ثبت‌اند. |
| سایر کنترل‌ها | `bash -n` و کنترل ساختار `global.json` موفق بودند. رفتار خطای اسکریپت build با فرمان شبیه‌سازی‌شده هم بررسی شد؛ جدا از build واقعی فوق است. |
| سامانهٔ قدیم و داده | هیچ باینری قدیمی اجرا نشد؛ به پایگاه واقعی یا دستگاه متصل نشدیم؛ migration و استقرار انجام نشد. |

## منشأ و صحت SDK

دانلود از میزبان مستقیم مایکروسافت در این محیط محدود بود. فایل SDK نسخهٔ `10.0.400` از ده قطعهٔ مخزن عمومی `andschir/dotnet-sdk-10.0.400-linux-x64`، commit `f4ca2352ed0e871c3adb118cf22ed86f7ff20c4e` از طریق `codeload.github.com` دریافت و بازسازی شد. اسکریپت شخص ثالث اجرا نشد. SHA-512 فایل بازسازی‌شده **پیش از استخراج و اجرا** برابر با هش متادیتای رسمی مایکروسافت در `dotnet/core` بود:

`1033977dd837150e0814cf0c5d5b17ceb63925fda7ba2158b47258a4bd7c048cf82eac3bc1166f3146f53124a3f5fba09db1de1260d2ce96399860303b404b48`

حجم فایل بازسازی‌شده ۲۴۰٬۱۳۳٬۶۹۲ بایت بود؛ آرشیوهای موقت پس از نصب حذف شدند و فایل بزرگ به مخزن اضافه نشد. برای نصب مجدد در محیط تازه، `tools/install-dotnet-sdk-linux-x64.sh` همین commit و checksum را استفاده می‌کند و نصب موجود را بازنویسی نمی‌کند. بازاجرای کامل آن در مسیر موقت شامل دانلود، تطبیق هش، استخراج و اجرای `dotnet --version` موفق شد؛ نسخهٔ آزمایشی دوم پس از آزمون حذف شد. حفاظت از بازنویسی نصب موجود نیز بررسی شد. `global.json` انتخاب SDK پایدار سری ۱۰ را هدایت می‌کند، اما خودش SDK را نصب نمی‌کند. نسخهٔ جدیدتر و به‌روزرسانی امنیتی در محیط بعدی باید جداگانه بررسی شود.

## بازاجرای بررسی پایه

```bash
cd ReCode
export PATH="$HOME/.local/bin:$PATH"
export DOTNET_CLI_TELEMETRY_OPTOUT=1 DOTNET_NOLOGO=1
./tools/phase02-verify.sh
```

`tools/phase02-verify.sh` نسخه را بررسی می‌کند و در صورت خطای build یا بررسی، غیرصفر خارج می‌شود؛ SQL یا مرورگر را تست نمی‌کند. [مرزهای معماری](Architecture.fa.md) اجزای موجود و حوزه‌های آینده را متمایز می‌کند.

## SQL آزمایشی و باقی‌ماندهٔ فاز

برای این فاز نمونهٔ **تازه و ایزولهٔ آزمایشی** SQL Server و `sqlcmd` در GitHub Actions فراهم و اتصال واقعاً بررسی شد. در Arena خود Docker/Podman، SQL Server و sqlcmd پیدا نشدند؛ جست‌وجوی مخزن در GitHub و npm برای بستهٔ قابل اعتبارسنجی موتور SQL Server نتیجه‌ای نداد. بارگیری ابزار رسمی `microsoft/go-sqlcmd` نسخهٔ `v1.10.0` از GitHub Releases در انتقال به `release-assets.githubusercontent.com` با EOF شکست خورد؛ نصب نشد و این ابزار در هر صورت خود SQL Server نیست. `unshare -Ur true` موفق شد، اما به معنی وجود محیط کانتینر یا دسترسی به ایمیج در Arena نیست. SQLite جایگزین آزمون SQL Server نیست.

راهکار اجراشده GitHub Actions با ایمیج رسمی SQL Server 2022 Developer بود؛ [اجرای نهایی موفق 42530655704](https://github.com/alirezarahimy-code/IO/actions/runs/42530655704) در commit `2b13ac5eb840c758289514208e14b0f8d245a296`، شامل build و بررسی کنسولی و آزمون SQL. متادیتای job موفقیت گام‌ها را تأیید می‌کند؛ annotationها نسخهٔ `16.0.4305.5 | Developer Edition (64-bit)`، digest ایمیج `mcr.microsoft.com/mssql/server@sha256:cf8f0ab2ebe61feec2eed2629061a07d247f791c2a8ddda74a4ac9f06a291718` و حذف کانتینر را ثبت کرده‌اند. دو اجرای پیشین `42530063657` و `42529949350` نیز موفق بودند. دریافت متن کامل log اجرای قبلی با EOF شکست خورد؛ نتیجهٔ گزارش‌شده از status گام‌ها و annotationهاست.

GitHub فقط فایل‌های `.github/workflows/` ریشه را به‌عنوان workflow شناسایی می‌کند؛ کاربر پس از توضیح این استثنا اختیار کامل اجرای آن را داد. فایل جدید `.github/workflows/io-phase02-sql-check.yml` ساخته و به شاخهٔ اختصاصی گفتگو push شد؛ فایل‌های اصلی قدیم تغییر نکرده‌اند. در workflow، `ACCEPT_EULA=Y` برای Developer آزمایشی تنظیم و رمز تصادفی در همان اجرای موقت تولید و mask می‌شود. ایمیج به digest مشخص ثابت شده و حذف کانتینر در صورت شکست باعث شکست job می‌شود؛ در اجرای نهایی annotation موفقیت حذف ثبت شد. پورتی روی میزبان منتشر نمی‌شود. `sqlcmd -N -C` اتصال رمزنگاری‌شده را با اعتماد به گواهی خودامضای همین محیط موقت استفاده می‌کند؛ آزمون اعتماد گواهی و امنیت TLS تولید نیست. قالب داخل `ReCode/ci/phase02-sql-check.yml` است. SQL Server محلی Arena هنوز مهیا نیست و تست‌های schema، migration، تراکنش و اتصال EF Core هنوز اجرا نشده‌اند.

اسکریپت `tools/phase02-sql-check.sh` صرفاً پس از opt-in با `IO_SQL_TEST_ONLY=yes` و `IO_SQL_TEST_SERVER` یک `SELECT 1` روی `master` اجرا می‌کند. اعتبارنامه نباید در دستور، فایل یا چت نوشته شود؛ در صورت نیاز از متغیرهای موقت sqlcmd استفاده شود. گزینهٔ `-N` به نسخهٔ sqlcmd و گواهی مورد اعتماد نیاز دارد و اسکریپت بررسی گواهی را دور نمی‌زند. آزمون اتصال به معنای اعتبارسنجی schema، migration یا تراکنش نیست؛ این‌ها در فاز ۳ سنجیده می‌شوند.

نسخه و نتیجهٔ اتصال آزمایشی بالا ثبت شده است. این نمونه پس از هر اجرای GitHub Actions حذف می‌شود و از Arena به‌صورت دائمی در دسترس نیست؛ برای آزمون‌های دیتابیس فاز ۳ باید workflow با تست‌های schema و برنامه گسترش یابد یا محیط محلی مجاز فراهم شود. نتیجهٔ فاز برای مرور ارائه می‌شود. به سیستم واقعی یا برنامهٔ قدیمی بدون مجوز جداگانه متصل نمی‌شویم. بدهی‌های فاز ۱ طبق [تحویل مشروط](../phase-01/Phase-Gate-and-Handoff.fa.md) پیگیری می‌شوند.
