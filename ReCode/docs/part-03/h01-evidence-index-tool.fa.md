# H01 — ابزار آفلاین نمایهٔ شواهد آزمایشگاه

این ابزار ادامهٔ عملی [بستهٔ H01](h01-final-windows-lab-handoff.fa.md) است؛ **هیچ اتصال شبکه/SQL، بارگذاری SDK، نصب سرویس، grant، فرمان یا حذف اجرا نمی‌کند**. تنها وجود و سازگاری ساختاری نمایهٔ ارجاع به شواهد خصوصی را بررسی می‌کند؛ دریافت/امضاسنجی/اثبات اصالت شاهد ندارد و بخش۳ یا H01 را خودکار تأیید نمی‌کند.

## اجرای Windows در محل آزمایشگاه

Python3 لازم است؛ وابستگی ثالث ندارد. یک پوشهٔ خصوصی خارج از checkout با ACL و سیاست نگهداری مصوب بسازید. نام پوشه مثال است، نه مسیر اجباری یا دستور تغییر ACL:

```powershell
python ReCode/tools/lab-h01.py --init D:\IO-Lab-Private\h01-index.json
# پس از اجرای واقعی سناریوها، فقط index را با ارجاع‌های خصوصی تکمیل کنید.
python ReCode/tools/lab-h01.py --check D:\IO-Lab-Private\h01-index.json
$LASTEXITCODE
```

پوشه باید از قبل وجود داشته باشد؛ `--init` هرگز فایل موجود را overwrite نمی‌کند. [نسخهٔ خالی](h01-evidence-index.template.json) نیز قابل کپی است؛ **pending/خالی** است و بررسی آن باید blocked شود. این نسخه شاهد اجرای دستگاه نیست. فایل واقعی را به Git، چت، artifact عمومی یا runner عمومی ارسال نکنید. مسیر جایگزین `ReCode/lab-results/` در ignore است، ولی ignore رمزنگاری، ACL یا محافظت در برابر `git add -f` نیست.

## چه چیزی ثبت می‌شود؟

- SHA چهل‌رقمی build، SHA256 شصت‌وچهاررقمی بستهٔ منتشرشده، نسخه‌های Windows/runtime/SDK و reference استقرار/آزمایشگاه واقعی. این‌ها declarations هستند؛ ابزار خود بسته یا امضای ناشر را verify نمی‌کند. hash را در محل با `Get-FileHash -Algorithm SHA256` از بستهٔ دقیق نصب‌شده بگیرید.
- حداقل۲ و حداکثر۳۲ alias دستگاه و reference هویت فیزیکی متمایز، model/firmware و قالب صریح `ssr` یا `legacy-int32`. reference هویت باید در مخزن خصوصی سازمان به serial واقعی متصل باشد؛ تمایز دو رشته، اثبات تمایز دو سخت‌افزار نیست.
- همهٔ۱۲ سناریوی H01 **برای هر دستگاه**، با زیرچک‌های مستقل: از نصب/هویت/دریافت/قطعی تا نوشتن، حذف‌های مختلف و unknown recovery. برای دو دستگاه۲۴ رکورد لازم است. سناریوی مشترکِ اختلال دو دستگاه، در هر دو رکورد به شاهد مشترک و رسیدهای همان دستگاه اشاره کند؛ یک نتیجه جای دو دستگاه را نگیرد.
- هر زیرچک یک reference غیرخالی؛ هر رکورد زمان گذشته/اکنون UTC با `Z`، اپراتور و بازبین مستقل، شاهد خصوصی و برای مسیرهای صف‌دار reference رسید. در رکورد نصب رسید SQL لازم نیست؛ اجرای واقعی SCM باید شاهد جدا داشته باشد. نبود رسید برای H01-08 مجاز است، ولی نبود شاهد نه.
- سناریوهای مخرب/بازیابی H01-09 تا H01-12 علاوه بر آن reference اختیار واقعی، اثر مدل، کنترل انحصاری و برنامهٔ recovery می‌خواهند؛ ابزار اختیار قانونی یا اثر SDK را از متن احراز نمی‌کند. زمان R15 نباید از گام‌های قبلی همان دستگاه زودتر باشد؛ این صرفاً کنترل timestamp اعلامی است، نه کنترل دستگاه.
- `review` بازبین مستقل و reference پذیرش ماتریس سناریو/مدل را لازم می‌داند؛ نام دو reference هویت، امضای رمزنگاری‌شده یا اثبات دو انسان نیست.

referenceها فقط شناسه‌های کوتاه ASCII با حرف/رقم و `._-` هستند؛ URL، مسیر فایل، متن چندخطی، رمز، template، عکس و لاگ خام جای آن‌ها نیست. شواهد اصلی باید pre/post count و state، نسخه‌ها و UUIDهای صف/رسید، تفاوت‌های firmware، مجوزها و امضای مسئولان را در مخزن امن سازمان نگه دارند. schema فیلد ناشناخته را رد می‌کند و خطاها مقدار ورودی یا مسیر فایل را چاپ نمی‌کنند؛ **این ابزار تشخیص یا پاک‌سازی مطمئن اسرار داخل identifierهای ظاهراً معتبر نیست**. نسخهٔ SDK/model نیز فقط اطلاعات غیرمحرمانهٔ محدود باشد.

## نتیجه و کد خروج

| وضعیت | خروج | معنا |
|---|---|---|
| ایجاد draft جدید |۰|فقط فایل pending ایجاد شد؛ هیچ تست دستگاه انجام نشد |
| `blocked` |۱|خطا/ناقص/عدم اجرا/شکست، فیلد اضافی، JSON تکراری/خراب، زمان نامعتبر یا شاهد/تأیید ناقص |
| `indexed-for-independent-human-review` |۰|صرفاً ساختار نمایه آمادهٔ بررسی انسانی است؛ **نه pass دستگاه یا بستن H01** |
| شکست ایجاد draft |۲|فایل موجود/پوشه یا مسیر نامناسب؛ فایل قبلی دست‌نخورده می‌ماند |

`pending`، `fail` و `not-run` نتیجهٔ آماده تولید نمی‌کنند. تنها H01-08 اختیاری PUSH/enroll/biometric می‌تواند با `unsupported`، `capabilityDisabled=true`، reference تعیین‌تکلیف و ارجاع هر زیرچک به disposition خصوصی ثبت شود. تفاوت setterهای مدل باید در ماتریس H01-06 تعیین‌تکلیف شود؛ کل تنظیمات یا حذف‌های لازم را نمی‌توان با unsupported دور زد. اگر نصب به حذف‌های مصوب دسترسی/اختیار ندارد، بسته **باز** می‌ماند؛ ابزار این کمبود را به موفقیت تبدیل نمی‌کند.

تمام خروجی‌ها و index باید `hardwareVerified=false` و `part3Complete=false` داشته باشند؛ ادعای true در ورودی رد می‌شود. اصالت شواهد همیشه `physicalEvidenceAuthenticityVerified=false` است. پذیرش واقعی، اگر بعداً انجام شد، **رکورد امضاشدهٔ مستقلِ مسئولان محل نصب** می‌خواهد؛ CI یا نتیجهٔ این ابزار جای آن نیست. factory reset و adapter USB/serial مستقیم همچنان ساخته نشده و این نمایه آن‌ها را فعال نمی‌کند.

## اعتبارسنجی خود ابزار

`ReCode/tools/ci-h01-tests.py` fixtureهای مصنوعی را در Windows CI بررسی می‌کند: template pending، پوشش تمام دستگاه/سناریوها، شناسهٔ تکراری، نتایج ناموفق، تأیید مستقل، زیرچک/رسید/اختیار حذف، زمان/ترتیب، عدم پذیرش خودکار، محدودیت۱MiB، JSON strict و خروجی بدون مقدار ورودی، عدم overwrite و exit-codeها. حتی fixture ساختاریِ موفق شاهد واقعی محسوب نمی‌شود. Linux طبق دستور کاربر تست نمی‌شود؛ اجرای این suite صرفاً تست ابزار است، نه اجرای H01.
