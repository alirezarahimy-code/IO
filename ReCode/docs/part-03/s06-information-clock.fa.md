# S06 — مشخصات، ظرفیت و ساعت؛ candidate نرم‌افزاری

این سند پذیرش سخت‌افزار یا اتمام بخش سوم نیست. مرجع آداپتر همان قرارداد استخراج‌شدهٔ Personnel.ZK.ZKDevice و IZKEM در `zk-reference-contract.json` است؛ فایل decompiled سورس اصلی نیست.

## مسیر و نقش‌ها

- صفحه `/workspace/device-information`، API `/device-operations` و جدول `DeviceOperations` مستقل از diagnostic است.
- `devices.info.read`: درخواست خواندن و مشاهدهٔ snapshot/تاریخچه؛ اپراتور و مدیر در **قالب جدید** دارند.
- `devices.clock.set`: تنظیم صریح، لغو pending تنظیم و بازبینی unknown؛ فقط قالب مدیر جدید دارد.
- `devices.operations.execute`: هویت worker؛ هیچ قالب انسانی خودکار ندارد. نقش‌های قبلی باید صریح grant/revoke شوند.
- مشاهدهٔ موجودی به `devices.read` نیاز دارد؛ هیچ حق خواندن به‌تنهایی مجوز تنظیم نیست. این حقوق فعلاً سراسری هستند، نه دامنهٔ تک‌دستگاه.

## نصب و اجرای امن

پیش‌نیازهای `device-worker-setup.fa.md`، SDK مجاز Windows با معماری صحیح، هویت فعال سرویس، SQL رمز‌شده، ACL فایل‌های child و key-ring/application-name مشترک برقرار باشند. COM در web بارگذاری نمی‌شود.

در تنظیمات worker علاوه بر `NativeEndpoints` پین‌شده، `IO:DeviceWorker:EnableOperations=true` لازم است. برای تنظیم ساعت، روی همان endpoint مقدار `AllowClockSet=true` لازم است؛ پیش‌فرض false است. این پرچم فقط اجازهٔ نصب است و **اثبات سازگاری مدل/firmware نیست**. تا آزمون آزمایشگاه آن را فعال نکنید. مجوز `devices.operations.execute` را صریح به نقش سرویس بدهید؛ diagnostic همچنان execute مستقل دارد.

## داده و زمان

خواندن: سریال پین‌شده، کد محصول، firmware، MAC، ساعت محلی دستگاه و شمارنده‌های تردد/کاربر/مدیر/اثر/چهره و ظرفیت‌ها. شکست هر فیلد یعنی null؛ صفر ساخته نمی‌شود. هیچ template بایومتریک دریافت نمی‌شود.

تنظیم: فقط UTC با ثانیهٔ کامل و `SET-CLOCK`؛ تبدیل با timezone ثبت‌شدهٔ محل نصب، رد زمان دیواری مبهم DST و فراخوانی `SetDeviceTime2` با اجزای صریح؛ نه ساعت محلی میزبان. هدف همان مقدار تأییدشده است و بابت تأخیر صف جلو برده نمی‌شود. clock pending بیش از دو دقیقه منقضی می‌شود.

## خطا و بازیابی

شناسهٔ idempotency ثابت؛ retry دقیق فقط همان رکورد را برمی‌گرداند. تغییر actor/device/version/نوع/هدف/مهلت رد می‌شود. هر دستگاه فقط یک diagnostic یا عملیات typed فعال دارد؛ چهار slot و چند worker می‌توانند دستگاه‌های مختلف را اجرا کنند. مهلت child حداکثر ۶۰ ثانیه و claim رهاشده بعد از دو دقیقه بازیابی می‌شود.

لغو فقط pending تضمین می‌شود. timeout/قطع فرایند یا claim رهاشدهٔ clock به `unknown` تبدیل می‌شود و هیچ write خودکار تکرار نمی‌شود. تا بازبینی، clock جدید و تغییر نسخه/رمز/گروه مسدودند. یک `information.read` تازه با ClockLocal معتبر از همان دستگاه/نسخه/timezone بگیرید؛ انسان snapshot را بررسی و `REVIEWED-CLOCK` را با نسخهٔ unknown ثبت کند. نتیجهٔ اصلی unknown می‌ماند، فقط پیوند مشاهده افزوده می‌شود. تغییر timezone محل نصب در این فاصله نیازمند بازگردانی تنظیم صحیح برای بازبینی است.

تاریخچهٔ SQL immutable و downgrade پس از ثبت رکورد با خطای 51017 مسدود است؛ پیش از ارتقا backup لازم است. DP/ACL و نصب SDK وظیفهٔ استقرارند. سریال pin احراز هویت رمزنگاری‌شده نیست.

## حدود شاهد

آزمون‌های قرارداد، child fixture، SQL/HTTP/DOM مسیرهای نرم‌افزاری را می‌سنجند، نه COM واقعی. هنوز خواندن/تنظیم روی مدل و firmware واقعی، دو دستگاه، قطع ارتباط و پذیرش Windows Service اجرا نشده است. سایر تنظیمات، کاربران S07/S08، تردد S09/S10، صف عمومی S11 و پذیرش S12 باز هستند؛ کنترل فیزیکی درب و payroll خارج دامنه‌اند.
