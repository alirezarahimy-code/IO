# نمایشگر موجودی واقعی محصول — بدون mock داده

این ابزار جای اجرای ASP.NET/SQL نیست. فقط یک فهرست/قاب مشاهده به **همان منابع واقعی و tracked** در `ReCode/src/IO.Web/Ui` متصل می‌کند. فهرست از `WorkspaceCatalog.cs` و توضیحات از `HelpContent.json` خوانده می‌شود؛ صفحات پیشنهادی `pages-first`، theme showcase، منابع legacy و fixtureهای تست در فهرست نیستند.

اجرا از ریشهٔ مخزن:

```sh
python3 ReCode/preview/actual-product/server.py --port 4180
```

- سرور روی `0.0.0.0` و URLهای نسبی است و به host پیش‌نمایش محدودیت localhost نمی‌دهد.
- هر HTML **بدون حتی تزریق banner یا بازنویسی DOM** از فایل اصلی سرو می‌شود؛ CSS و JavaScript هم همان فایل‌های اصلی‌اند. هدر `X-Product-Source-SHA256` برای تطبیق بایت‌هاست. فقط پوستهٔ بیرونی انتخاب صفحه برای نمایشگر جدید است، نه صفحهٔ جدید محصول.
- حالت پیش‌فرض «چیدمان» با CSP اجرای JavaScript را می‌بندد تا فرم‌های موجود بدون نیاز به ورود/SQL قابل مشاهده باشند؛ فرم submit نمی‌شود. hiddenهای خود فایل دست‌کاری نشده‌اند. متن اولیهٔ «درحال دریافت» واقعاً متن قالب است، نه شاهد لود داده.
- حالت «اجرای JavaScript اصلی» همان اسکریپت را اجرا می‌کند، ولی APIهای محصول پاسخ صریح `503 preview-backend-unavailable` می‌دهند. نه `[]`، نه آمار صفر، نه permission/capabilities، نه CSRF token، نه حساب نمایشی و نه موفقیت عملیات جعل نمی‌شود. مخفی‌شدن فرم توسط منطق اصلی مجوز، به معنای نبود سورس آن فرم نیست.
- تمام mutationها سمت سرور رد می‌شوند؛ iframe و CSP ارسال فرم/ناوبری سطح بالا را هم محدود می‌کنند. DB/SDK، credential یا عملیات روی دستگاه وجود ندارد. برای فرم ورود هم رمز واقعی وارد نکنید.
- کاتالوگ فایل فیزیکی را بررسی می‌کند؛ نمایش صفحه، اثبات تکمیل تمام رفتار/API/پذیرش سخت‌افزار آن نیست. شمار فعلی۵۸ مسیر روی۵۲ HTML مشترک/مستقل است، نه۵۸ طراحی مستقل.
- source viewer این سرور فقط برای محیط توسعه/بازبینی است؛ برای استقرار production یا پابلیک‌کردن کد محصول به کار نرود. هیچ احراز هویت محصول دور زده نشده چون backend محصول اصلاً در این سرور اجرا نمی‌شود.
