ارسال عادی کاربران؛ نتیجهٔ مستقل هر نفر/دستگاه

پنل · دریافت و پیش‌نمایش هدف

فقط مدل SSR حضور و غیابِ تأییدشده در آزمایشگاه؛ نه دستگاه کنترل درب. این صفحه password، privilege، AccGroup، قالب یا عکس ارسال نمی‌کند. ساخت کاربر جدید عمداً بدون password است. نام از کارمندِ دارای نگاشت معتبر گرفته می‌شود و بریده نمی‌شود. نام بیش از ۲۰ نویسه یا تغییر admin پشتیبانی نمی‌شود. کارت خالی یعنی پاک‌کردن کارت با تأیید شما.

پیش‌نمایش یک صفحهٔ ارسال (۱ تا ۵۰ نفر/دستگاه)

هر سطر JSON یک مقصد مستقل است: id، deviceId، expectedDeviceVersion (base64)، snapshotId دریافت موفق S07 همان هدف، employeeId، personIdentifier دقیق، card رشتهٔ عددی یا خالی، enabled و timeoutSeconds (۱–۶۰). برای چند دستگاه چند سطر بسازید. این بودجهٔ صفحه است، نه سقف کاربران/دستگاه‌های محصول.

افزودن یک فرد/دستگاه به صفحه

برای همان فرد روی دستگاه دیگر، مقصد، نسخه و snapshot را عوض و دوباره اضافه کنید. برای retry انتخابی فقط افراد نیازمند بررسی را در صفحهٔ تازه بگذارید؛ موفق‌ها را تکرار نکنید.



تاریخچه و نتیجهٔ هر نفر/دستگاه
    

    بازبینی نتیجهٔ نامعلوم؛ نه تکرار خودکار
    ابتدا دریافت S07 موفق و تازهٔ همان دستگاه/نسخه را انجام دهید و وجود/عدم وجود و دادهٔ فرد را بررسی کنید. ثبت این بازبینی نتیجهٔ قبلی را succeeded نمی‌کند. retry فقط با intent و snapshot جدید است؛ افراد موفق را دوباره انتخاب نکنید.
