زمان‌بندی پایدار دریافت SDK

پنل · دستگاه‌ها · اصل tuple و قرنطینه با مجوز مستقل

این صفحه polling خواندنی SSR است، نه PUSH. هر پنجره یک درخواست و تاریخچهٔ واقعی SQL دارد. فقط دریافت کامل cursor را جلو می‌برد. با انتخاب ثبت خودکار، هر صفحه زیر اختیار فعلی سازنده در هستهٔ raw بررسی می‌شود؛ ناشناس/تاریخ نامعتبر در قرنطینه می‌ماند. موفقیت run به معنی ثبت همهٔ ردیف‌ها یا محاسبهٔ کارکرد نیست.

توقف، درخواست pending را لغو می‌کند؛ خواندن running ممکن است تمام شود، ولی ثبت خودکار آن زمان‌بندی متوقف می‌شود. retry خودکار فقط خواندن است، نه نوشتن یا پاک‌سازی دستگاه. worker و هر endpoint باید جداگانه و صریح فعال شوند. آزمون واقعی مدل هنوز لازم است.

بازخوانی هم‌پوشان فقط با مقدار مصوب انجام می‌شود؛ cursor عقب نمی‌رود و tupleهای تکراری از dedup موجود عبور می‌کنند. رویداد دیررس بیرون این بازه تضمین نشده و به دانلود بازه‌ای مستقل نیاز دارد؛ این قابلیت PUSH نیست.
