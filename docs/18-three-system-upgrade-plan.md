# برنامهٔ دقیق ارتقای نسخه — سه سامانه: TWF (آریا) · T5Web (آریا ادمین) · Link5

> **سند تاریخی، نه برنامهٔ اجرای فعلی.** دامنه و ترتیب بعداً اصلاح شد: اکنون فقط دو محصول مستقل `net10.0`، **اول آریا** و سپس ادمین، با Link5 خارج از پورت. برنامهٔ فشردهٔ جاری و گیت‌های واقعی در [`src/net10/FAST_TRACK_PLAN.fa.md`](../src/net10/FAST_TRACK_PLAN.fa.md) است؛ برآوردها/ترتیب «ادمین اول» در متن زیر مبنای اقدام نیستند.

**سؤال:** «برای هر سه سامانه، دقیقاً چه کاری باید بکنیم تا نسخه بالا برود، بدون خرابی؟»

**پاسخ کوتاه:** دو سامانهٔ بازنویسی‌شده (`TWF`, `T5Web`) هر دو امروز روی
**.NET Framework 4.7.2 / MVC 5** هستند و هدف **`net10.0` / ASP.NET Core** است. فاصله‌شان
اندازه‌گیری شده و **خیلی متفاوت** است: ۲۵۰ نقطهٔ کوپلینگ در T5Web، ۹۰۵ در TWF.
سامانهٔ سوم (`Link5`) **سورس ندارد** — نسخهٔ آن اصلاً بالا نمی‌رود؛ تصمیمش «جانشینی یا
حفظ» است، نه «ارتقا». جزئیات هر سه در ادامه، با شناسهٔ کار، معیار پذیرش و گِیت CI.

### ۱.۱ تفاوت تعیین‌کنندهٔ دو سامانه

T5Web توانست قفل پلتفرم را با **جایگزینی یک فایل** بردارد (`SqlEngineDirectory`).
TWF نمی‌تواند: موتور T5 مستقیماً در **۳۰ کنترلر** صدا زده می‌شود —

```
engineCallSites = 401  in 36 files
AcceptRequestController 44 · HomeController 32 · HourlyLeaveController 21 ·
EditRequestController 20 · UndoController 20 · HourlyDutyController 19 …
T5V3DBManager 118 · RequestDA 115 · RequestAcceptDA 32 · PersonnelDeputyDA 28 · LeaveTypeDA 26
T5V3.LeaveCalcs 4 files · T5V3.Attendance 11 files · T5V3.ReportGenerator 1 file
```

و مهم‌تر: این‌ها فقط خواندن دایرکتوری نیستند؛ **موتور محاسبات** (`T5V3.Attendance`,
`T5V3.LeaveCalcs`) هم داخل همین مسیر است. این تفاوت، دو برنامهٔ متفاوت می‌سازد.

### ۱.۲ یک نکتهٔ مهم دربارهٔ TWF

سِیم (seam) درست **از قبل ساخته شده**: `TWF.Domain/Interfaces/IT5BackendAdapter.cs` با
~۷۰ متد و دو پیاده‌سازی (`T5V3BackendAdapter` ۱۰۴۷ خط، `InMemoryT5BackendAdapter` ۹۶۴ خط).
یعنی معماری برای پورت آماده است؛ فقط ۳۰ کنترلر از آن **عبور نمی‌کنند** و مستقیم به
`*DA`ها می‌چسبند. بنابراین کار TWF «طراحی دوباره» نیست، «عبور دادن ۴۰۱ فراخوانی از
درِ موجود» است.

## ۴. سامانهٔ ۲ — TWF (آریا): بزرگ‌ترین فاصله، ولی مسیر روشن

**فاصله:** ۹۰۵ نقطه — ۴۴ فایل `System.Web`، ۳۰ کنترلر، ۷۴ ویو، **۴۰۱ فراخوانی موتور**،
۲ فایل `System.Web.Hosting` (`VirtualPathProvider`)، ۲ فایل `System.Web.Http` (Web API 2)،
۴ فایل `WebConfigurationManager`، ۳ فایل `System.Drawing`.
همچنین: **TWF هیچ‌وقت در CI ساخته نشده** — یعنی امروز حتی یک عدد قابل‌اعتماد از
«کامپایل می‌شود» نداریم.

## ۵. سامانهٔ ۳ — Link5: نسخه بالا نمی‌رود، چون سورس ندارد

**واقعیت:** `Link5 v4.0.4` یک محصول **باینری** است (`.NET Framework 4.8`, x86, WinForms +
`Comm5Service v4` + `Link5.Service` + `WatchDog` + `SDK 6.3.1.45` = ZKTeco). هیچ فایل `.cs`
در مخزن ندارد. پس «بازنویسی و ارتقا» به‌معنای TWF/T5Web ممکن نیست.

**ولی خبر خوب:** `.NET Framework 4.8.1` روی Windows Server 2025 **درون‌سیستمی** است؛
Link5 امروز و فردا اجرا می‌شود و ارتقای دو سامانهٔ دیگر به آن کاری ندارد. تنها چیزی که
Link5 را به ما وصل می‌کند، **قرارداد** است:

| شناسه | کار | معیار پذیرش | تخمین |
| :-- | :-- | :-- | --: |
| **L5-0** | تثبیت قرارداد: پایگاه `Personnel`/`Record` + HTTP `127.0.0.1:15222/Device/` (۳۲ کنش) | سند قرارداد + تست قرارداد روی پاسخ‌های واقعی | ۱ |
| **L5-1** | Link5 در ماشین/VM جدا (خارج از محدودهٔ ارتقا) و **بدون ارتقا** نگه داشته شود | چک‌لیست: نسخه، مسیر، سرویس‌ها، پشتیبان | ۱ |
| **L5-2** | ۵ کنش باقی‌ماندهٔ دستگاه در T5Web از طریق همان قرارداد تأیید شوند | `T43` موجود + یک تست قرارداد واقعی (نیازمند یک Link5 زنده) | ۲ |
| **L5-3** | تصمیم «جانشینی» فقط اگر لازم شد: بازنویسی لایهٔ دستگاه (iclock/ATTLOG/Push) | پروژهٔ مستقل؛ **پیش‌نیاز: دستگاه واقعی برای تست** — امروز نداریم | ۱۰–۲۰ |

**پیشنهاد: L5-3 را الان شروع نکن.** بدون دستگاه واقعی، هر بازنویسی فقط روی کاغذ سبز
می‌شود. تا وقتی Link5 کار می‌کند و روی همان ماشین می‌ماند، «نسخه» مسئلهٔ ما نیست؛
مسئلهٔ ما قرارداد و قابل‌جانشینی بودن است — که با L5-0/L5-2 خریداری می‌شود.

> اگر تصمیم شما چیز دیگری است (مثلاً می‌خواهید Link5 هم حذف شود)، فقط بگویید؛ برنامه
> عوض می‌شود، ولی هزینه و پیش‌نیاز (دستگاه) عوض نمی‌شود.

## ۸. ریسک‌ها و بازگشت

| ریسک | اثر | کاهش |
| :-- | :-- | :-- |
| `AdminAuthorize` (T5Web) / ماتریس مجوز (TWF) اشتباه پورت شود | «همه‌چیز کار می‌کند، فقط بعضی‌ها بیشتر می‌بینند» | تست ماتریس نقش×مسیر **قبل** از پورت؛ هارنس برای مسیرهای محافظت‌شده |
| محاسبات مرخصی/اضافه‌کاری (TWF) با بازنویسی تغییر کند | اعداد اشتباه در فیش و کارکرد | راه (ب): موتور دست‌نخورده در عامل؛ راه (الف) فقط با مقایسهٔ خروجی واقعی |
| `System.Drawing` روی Core | تولید عکس/بنر در محیط غیرویندوز می‌شکند | استقرار ویندوزی (هدف ماست) + تصمیم `System.Drawing.Common` یا `ImageSharp` |
| از دست رفتن «رفتار فعلی» به‌عنوان مرجع | دیگر نمی‌دانیم درست است یا نه | نسخهٔ Framework تا پایان روی IIS می‌ماند و جواب می‌دهد |
| بودجه/زمان | ادعای ارتقا بدون پنج شرط §۲ | همان جدول §۲: تا سبز نشده، اعلام نشود |

**بازگشت (Rollback):** هر دو سامانه در طول پورت روی Framework **کار می‌کنند**؛ جابه‌جایی
یک استقرار است با: (۱) پشتیبان DB، (۲) نگه‌داشتن app pool قبلی، (۳) اسکریپت بازگشت
`deploy/`، (۴) پنجرهٔ زمانی کوتاه و قابل‌برگشت.

## ۹. تصمیم‌هایی که از شما لازم است

1. **TWF:** راه (ب) — سرویس عامل محاسبات — تأیید می‌شود؟ (پیشنهاد ما) یا (الف) بازنویسی
   محاسبات، یا (ج) ماندن روی Framework؟
2. **Link5:** در VM/ماشین جدا نگه داشته شود (پیشنهاد ما) یا جانشینی (L5-3) شروع شود؟
   جانشینی **بدون دستگاه واقعی** قابل‌تأیید نیست.
3. **هدف زمانی:** T5Web اول تمام شود (۲۷ واحد) یا هر دو موازی؟ موازی یعنی دو شاخهٔ کاری
   و دو برابر سطح تمرکز؛ ترتیبی امن‌تر است.
4. **TWF-0:** ساخت TWF در CI همین حالا شروع شود؟ (مستقل از پاسخ ۱، لازم است.)

## ۱۰. آنچه در این برنامه **نیست**

- تاریخ تقویمی: «واحد کار» = یک برش کاری که با CI تمام می‌شود؛ تبدیل‌کردنش به هفته بدون
  دانستن ساعت کاری شما حدس است.
- تغییر رفتار: هیچ مسیر، صفحه، مجوز یا تستی عمداً تغییر نمی‌کند. تنها تغییر رفتاری
  شناخته‌شده، افزودن محافظت CSRF به TWF است (§۴.۲) که جداگانه تصمیم می‌شود.
- Link5: هیچ کدی برای بالا بردن نسخهٔ آن نوشته نمی‌شود، چون سورس ندارد.
